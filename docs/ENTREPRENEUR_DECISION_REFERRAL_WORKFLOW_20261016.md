# 企业家健康决策计划：报告解析转介闭环

适用对象：服务名称为“企业家健康决策计划”的订单。这里的“专科回复”指专科医生在原转介上提交报告解析意见，不是健管专员代写医疗结论。

## 岗位与流转

1. **健康规划师受理**：核对订单与客户需求，交客户所属健康顾问；保留原订单全程督办，不能在此时结束工作台任务。
2. **健康顾问确认方案并发起转介**：确定医院、院区、科室、专家、预计解析时间和服务方式（远程、医院门诊等）。填写转介目的、待解答问题、附带报告及客户授权范围，向选定专科医生提交转介。方案和转介记录均关联原订单。
3. **健管专员预约及沟通**：依据顾问确认的资源安排预约，与客户核对实际时间、地点或远程接入方式，记录预约结果、沟通情况和变更。医院、科室或专家需变更时退回顾问重新确认，健管专员不能自行替代专业选择。
4. **专科医生解析并回复**：预约确认后，专科岗位任务解锁；医生在原转介中接单，完成报告解析后提交分析、专业意见、来源与日期、后续建议和相关资料。回复保留作者及版本；预约完成不能代替专业回复。
5. **健康顾问审核归档**：核对专科反馈与原问题、报告来源和预约记录；可退回补充。通过后归档转介与解析结果，明确交给客户的结论或后续事项，标记服务专业环节完成。
6. **健康规划师最终确认**：核对客户沟通、预约履行、专科反馈和顾问归档。记录验收结论后，关闭原订单服务及工作台任务；此前任何单一环节完成均不自动结单。

## 系统约束

- 各环节只由对应岗位或超管操作，按原订单和服务对象校验权限与机构隔离。
- 每个订单每一环节只有一条当前任务；重复提交不重复创建任务、转介或扣减次数。
- 任务展示当前负责人、计划与实际时间、服务方式及进展；逾期只提示，不自动越过审核。
- 退款或取消时关闭未完成岗位任务，保留已提交的转介、回复和审核历史。
- 专科在线回复依赖医疗专家资源关联有效医护账号。未关联账号时，现有系统只支持线下联系和资料归档；若业务要求专家本人直接在线提交，需要先确定外部账号或受限回复入口。

## 现有能力与缺口

- `Referral` 已支持顾问发起、专科接单和反馈、反馈修订历史，并可由医疗专家资源关联医护账号。
- 专业评估流程已有专科回复后的顾问终审工作台任务。
- 本次本地代码已把原订单任务、顾问转介、健管预约、专科回复、顾问归档和规划师验收按订单关联；旧通用随访编辑、删除、直接核销和提前结单入口已拦截。顾问从客户报告中显式选择本次授权给专科的原件，专科从原转介受限打开。需要补充时，顾问在审核环节退回，专科修订原反馈并保留版本。同一专科环节只建立一条订单工作台任务，不重复生成专业评估任务。
- 这套代码尚未部署；本地验证包括后端定向回归与员工端生产构建。需要在测试环境用四个真实岗位账号及一笔测试订单完成页面和权限验收，再考虑发布。
