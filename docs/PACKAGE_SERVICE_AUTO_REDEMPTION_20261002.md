# 服务包次数自动核销（2026-10-02）

- 权益来源以已购买或已生效的服务包为准；会员类型仅用于展示、筛选。共享次数按池扣一次，独立服务按对应商品扣一次。
- 年度营养访谈由营养师核实并完成后，以及营养领域的阶段性评估正式归档后，分别按对应的服务完成来源核销营养干预商品。就医类订单必须有明确的年度服务需求关联，且服务订单整体完成后才核销；单独付费订单不扣服务包次数。
- 从权益发起服务时先预占一次；履约订单完成后改为已核销，取消或退款且尚未完成时释放预占。同一完成来源用确定性键防止重复扣次。
- 历史生效但没有订单权益快照的服务包，首次新服务完成时冻结当前配置并记录新核销。历史用量未知，页面不显示确定剩余次数，人工预占前须先核对历史。异常在医护端权益卡提示核对。

## 2026-10-02 套餐优先与实际启动

- 客户购买同商品服务时，后端先匹配有效且历史余额已核对的套餐权益。最早到期的可用权益生成零元履约单并原子预占一次；无余额时正常进入付费结算。已付款历史订单保持原样，不追溯改为套餐单。
- 历史用量未核对的匹配套餐会阻止再次付款，提示超管先核对，避免重复收费或按未知额度超用。
- “安排服务”只是预约，不核销。医护确认实际启动并填写服务内容后，单次套餐服务自动把预占转为核销；多次服务仍逐次留痕，全部完成后才核销套餐。启动前取消释放预占；已实际启动的次数不退回。
- 客户端结算成功信息按套餐单显示为零元，健康基金和优惠券不消耗；App 与小程序同步展示。

## 历史次数核对入口

- 医护端超级管理员打开客户详情 → 会员权益，可直接看到“核对历史次数”；消费记录 → 服务核销保留同一入口。该操作只核对旧生效套餐的历史已用次数及依据，新购买并生效的套餐无需此审核。
- 打开权益时系统为旧生效套餐建立待核对台账，以便入口出现；建账不认定历史余额，也不扣次。非超管看到明确的责任人提示。
- 客户编号仍采用 `KH-` 加创建客户时的 24 位唯一 ID，系统自动生成且永久不变；客户列表支持完整编号搜索。它是身份编号，不是可编辑的会员卡号。
- 会员权益标题栏为医护端超管固定显示“核对历史次数”；是否待核对由服务端权益摘要返回，避免旧台账存在但前端推断条件未命中时入口消失。点按后直接打开该客户核对表。
- 后台扫描由 `PACKAGE_SERVICE_AUTOREDEEM_FROM`（ISO 时间）开启，仅重试该时间之后完成的营养任务与服务订单，不批量回填旧完成记录。
- 医护端“会员权益”展示已购买/生效计划；“消费记录”集中展示订单逐次核销、套餐预占与自动核销记录。历史生效服务包由超级管理员输入上线前各共享池/独立服务已用次数及核对依据，系统与上线后记录合并计算余额，并留下审计；未核对前不显示确定可用次数。
- “消费记录”将套餐包含的商品显示为 ¥0 待发起清单行，与单独购买订单并列并标明来源。次数权益本身不是订单；选定具体服务时才预占一次并创建 ¥0 履约单。营养评估仍由正式完成事件自动核销，避免同时创建独立履约单而重复扣次。

## 就医协助衔接

- 健康顾问发起医疗代诊或陪同类服务时，系统按实际服务名匹配有效套餐中的具体商品，先用最早到期的权益并预占共享池一次；历史未核对、规格有歧义或次数用尽时停止发起。若对应付费商品已上架而无套餐权益，提示先购买，不创建免费服务单。临时加诊和代配服务沿用原有独立流程。
- 创建方案本身不扣次。消费记录中选择具体套餐服务时也自动匹配最早到期的权益；单次套餐履约单在填写实际启动内容后自动核销，尚未启动而取消时释放预占。
- 单次已付款服务由负责的健康规划师或超管确认实际启动并填写内容后自动核销一次；若未提前确认启动，就医执行流程完成时补记一次，防止漏核销。存在后续执行任务的订单继续保留任务至结案，佣金在结案后计算；历史已付款订单不改为套餐单。多次服务保留逐次完成记录。
