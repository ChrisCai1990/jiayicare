# 嘉医汇健康管家｜SDK 与权限对照表（提审版草案）

更新时间：2026-09-24  
依据：当前 `app/package.json`、`app/app.json` 及实际调用代码。  
用途：用于各应用商店隐私表单、SDK 清单和审核备注；外部服务商名称须由生产环境配置与采购/法务资料最终核实后填写。

## 一、终端权限

| 权限 | 触发页面/动作 | 目的 | 是否首次使用时申请 | 拒绝后的处理 |
| --- | --- | --- | --- | --- |
| 相机 | 血压拍照、体检资料拍摄 | 用户主动拍摄并上传健康资料 | 是 | 提示可改用相册或手工录入，不阻断其他功能 |
| 相册/图片 | 上传体检资料、血压照片 | 用户主动选择已有图片 | 是 | 提示授权或改用其他上传方式 |
| 文件读取 | 选择 PDF/文件型体检资料 | 用户主动选择文件 | 由系统文件选择器处理 | 取消选择即返回，不读取其他文件 |
| 网络 | 登录、同步档案、服务沟通、上传资料 | 与 `https://jiaycare.com/api` 加密通信 | 系统网络能力 | 网络异常提示重试 |

> 当前 Android 明确声明：`CAMERA`、`READ_MEDIA_IMAGES`。没有发现定位、通讯录、短信读取、麦克风或后台定位声明。

## 二、客户端组件/SDK

| 组件 | 用途 | 是否独立向外部服务发送个人信息 | 商店隐私表单口径 |
| --- | --- | --- | --- |
| Expo / React Native / React Navigation | 应用运行与页面导航 | 否，属客户端基础框架 | 按实际版本及官方说明填写 |
| expo-image-picker | 调用相机/相册供用户选取资料 | 仅在用户选择后将选中内容交由本应用上传 | 说明相机、照片权限用途 |
| expo-document-picker | 选择用户主动指定的文件 | 否 | 说明文件选择用途 |
| expo-image-manipulator | 在本地压缩/旋转图片 | 否 | 不作为第三方数据接收方 |
| expo-file-system | 本地读取临时上传文件 | 否 | 不作为第三方数据接收方 |
| expo-av | 播放已获授权的语音内容 | 不直接采集麦克风 | 不申请录音权限 |
| @expo/vector-icons / react-native-svg / gifted-charts | 图标与本地展示 | 否 | 不作为第三方数据接收方 |

## 三、服务端/第三方处理项：提交前必须核实

| 服务类别 | 代码可见用途 | 可能涉及的信息 | 提交前要补的事实 |
| --- | --- | --- | --- |
| 短信服务商 | 登录、换绑手机号验证码 | 手机号、验证码发送记录 | 服务商名称、隐私政策链接、存储/处理说明 |
| 云服务器与数据库/对象存储 | 账号、健康档案、图片和报告的存储与读取 | 账户信息、健康信息、上传资料 | 云厂商名称、地域、加密、保存期限、访问控制 |
| AI 服务 | 健康内容整理、AI 对话或报告辅助处理（仅在功能实际启用时） | 用户主动提交的内容及最小必要上下文 | 实际模型/供应商、是否出境、单独同意与人工审核边界 |
| 语音合成服务 | 用户主动播放文本语音 | 待播报文字 | 代码注释指向阿里云语音合成；须以生产配置核实服务商、隐私政策及调用范围 |
| 支付服务 | 服务订单的支付选择 | 订单信息、支付状态 | 实际支付渠道、接入方式、是否跳转至支付机构页面 |

## 四、提交前禁止项

- 不凭代码推测填写云厂商、短信、AI 或支付供应商名称。
- 未实际启用的 SDK/权限不写入商店隐私表单；实际启用而未披露的不得提交。
- 健康信息属于敏感个人信息，涉及 AI、报告识别或服务人员访问时，须与公开隐私政策中的单独同意和最小必要规则一致。
