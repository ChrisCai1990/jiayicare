# GEO 内容渠道与 App 小程序承接设计

## 结论

GEO 内容的权威原文必须发布在无需登录的公开知识中心；App 和小程序不作为唯一内容源，而是承担阅读延续、测评、登录建档、预约和服务转化。

## 用户路径

```text
AI 搜索 / 百度 / 微信搜索 / 内容平台
  -> 公开知识中心的单篇内容 URL
  -> 3 分钟代谢健康风险测评
  -> 小程序或 App 打开
  -> 登录、建档、预约
  -> 健康管理师承接
```

## 各渠道职责

| 渠道 | 用户看到什么 | 主要目标 | 不承担什么 |
| --- | --- | --- | --- |
| 公开知识中心 | 完整、可审核、可引用的专题和问题内容 | GEO/SEO、建立信任、测评导流 | 个人健康档案、私密咨询 |
| App | 已登录用户的内容推荐、收藏、测评结果、服务进度 | 留存、服务体验、转化承接 | 唯一公开索引源 |
| 小程序 | 微信内快捷阅读、测评、分享与预约 | 社交传播、低门槛转化 | 唯一公开索引源 |
| 公众号/视频号/抖音/小红书 | 单问题短内容与专家解释 | 触达、测试选题、回流权威页 | 承载全部医学说明 |

## App 和小程序首版能力

1. 首页或服务商城增加“健康知识”入口，先只展示已经专业审核的专题卡。
2. 内容详情采用公开知识中心 URL；打开后保留来源参数和专题编号。
3. 每篇内容只提供一个行动入口：测评、资料准备清单或服务匹配。
4. 用户完成测评后，再进入小程序/App 登录、授权和建档流程。
5. 已登录用户可在 App/小程序查看“我的测评”和后续服务状态；不要把全部公开科普复制成仅登录可见的页面。

## 技术衔接

- 公开页面链接形态：`/guides/metabolic/{topic-slug}/`。
- 承接链接携带：`topic_id`、`utm_source`、`utm_medium`、`utm_campaign`。
- App 和小程序读取上述参数后，写入线索的首次来源与落地专题；不得将健康信息写入 URL。
- 公开站点与 App/小程序使用同一份经过审核的内容源，但采用不同展示模板，防止内容事实不一致。

## 首发顺序

先发布公开专题页和 3 至 5 篇高意图问题页；随后在小程序首页和 App 首页增加专题入口。这样既能尽早积累可引用内容，也不会让 App 上架进度依赖全部内容站建设完成。
