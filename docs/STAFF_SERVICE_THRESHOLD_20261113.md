# 员工基础服务业务量与服务费门槛

2026-11-13 用户确认：员工有基础薪酬，月度服务业务量达到个人门槛后，**只对超出门槛的部分**计提服务费。随后补充：月度与季度都要满足；某月超额但其他月份不足，季度总体不足时不能发放该月服务费。

## 配置与口径

- Admin「佣金规则 → 员工」按人设置**全部产品、全部类别合计**的月度基础服务业务量，单位元；不随页面的产品选择变化。季度门槛为月度门槛的三倍。`0` 表示不设门槛；服务费比例仍按该员工适用的产品规则决定，没有服务费规则则不产生个人服务费。
- 服务业务量取订单购买时冻结的服务归属拆解，以及实际完成、核销的人员和时间；产品、检测和企业资源归属不计入个人服务门槛。同一笔企业现金收入只入账一次。
- 按北京时间自然月累加实际完成的净实收服务归属。分次核销跨月时逐次计入对应月份。先逐月计算超额，再以季度三个月总业务量减季度门槛作为最终计提上限；季度总量不足则该季度服务费为零。月度超额按事件顺序比例分配季度上限，分币尾差由最后一笔承担。
- 退款或订单取消后重算对应业务量和应计服务费。已付款差额保留待追回标记和原付款记录，不直接抹除。
- 服务费须同时满足实际完成、自然季度结束和订单支付满 30 天，才可进入审核发放。规则按完成时有效版本记录，已产生的订单不因之后改比例自动改写。
- 团队负责人对成员实际服务的奖励独立于成员个人服务费门槛；如管理员配置团队规则，按已完成服务归属另行计提，不重复增加企业营收。

## 本地实现与验收边界

本工作树已增加员工门槛规则模型、管理端月度与季度查询、季度封顶结算重算和订单取消保护。相关单元测试覆盖超额计算、北京时间月界、跨月核销、取消订单、跨产品月度累计及季度不足时不计提。隔离 MongoDB/JWT/HTTP 流程已验证保存员工 ¥3,000 月门槛、完成 ¥4,000 服务后显示本月超额 ¥1,000，同时为该员工团队负责人产生独立的已完成服务奖励；Admin 构建通过。**尚未部署生产，未进行真实支付或财务付款验收。**

上线前需在隔离数据库跑完整订单链路，重点核对多人同单、多次核销、跨月退款和已付款追回应计；再由财务确认门槛金额及员工适用的服务费比例。门槛金额由管理员自行设置，系统不预填任何员工的实际目标。
