# 已派发待执行固定事项改期（功能分支，未部署）

## 范围

续约凭据更正已有规划师申请后，健康顾问可以在固定日期修订区域额外勾选“包含已派发待执行任务”。请求显式使用 `revise_planned_fixed`，需填写原因、确认影响。默认仍是原未派发修订策略，不把旧审核扩权。

- 仅原日期一致、稳定键精确且唯一、状态 `planned`、没有执行痕迹/服务依赖/关联的年度固定事项。就医、会诊、检查完善、复查、接种、功能医学及年度体检沿用现有日期字段。
- 同日同名、历史旧键或缺版本的事项保守阻断；不会猜测一条任务属于哪项。目标之外的已完成记录不修改。
- 不改冻结年度方案、负责人、内容、状态、任务编号和派发键。仅改任务日期、按原时间差平移提醒、同步服务需求中日期快照；新增任务内 `annualScheduleHistory` 保留前后日期、提醒日期、审核人及原因。服务期更正历史记录受影响任务ID。
- 已开始、已完成、取消、错过、已关联服务、相对周期、补给、启动任务、跨年份迁移不在此入口开放。脱离凭据更正的独立改期也未开放。

## 原子性与恢复

新策略必须使用 MongoDB 多文档事务：先条件写服务期文档形成写入屏障，在同一 session 下重新校验凭据及审核影响快照，精确映射任务并查权威服务关联，再逐条条件更新任务，最后提交日期覆盖层、生效凭据与审计。所有数据库操作串行使用该 session，读取 snapshot、提交 majority。

- 任一任务版本/日期/状态变化，或凭据/关联/期间校验失败，整批回滚。没有“第一条改了、第二条失败”的持久中间状态；旧申请保留并进入原岗位工作台重试/重新审核。
- 重复调用以更正ID、版本及状态判断，已应用不重复追加任务审计。未知提交结果也不能用旧条件覆盖已应用状态，后续读取真实状态。
- 原订单与历史订单唯一占用检查继续保留，不释放旧订单。事务不替代订单索引和派发索引要求，也不保证未来退款不会发生。
- 数据库不支持事务时**不降级为普通逐条写入**，原任务和凭据不变，规划师工作台提示联系管理员核验环境。

## 两个并发窗口

1. 续年同步现在禁止抢占 `syncState=running`，并等待所有并行派发分支结束后才写回 idle/failed。此前 `Promise.all` 提前拒绝可能让另一个分支继续写，已改为 `allSettled` 后处理错误。新同步仍校验凭据更正版本，不能拿改期前快照启动。
2. 年度服务需求首次建立关联前，先用任务日期/updatedAt/状态条件把需求与随访标记 `in_progress`。这会与改期事务写冲突，封住关联已创建但投影尚未回写的窗口。任一失败停止创建关联，已标记开始的不回退；原服务入口刷新后可继续。非年度关联和订单原岗位流转不改变。

## 部署前要求及尚未验收

- 必须确认部署 MongoDB 是支持事务的副本集或分片拓扑；现有文档只写本机 MongoDB，**不能据此认定已有事务能力**。本轮没有改 MongoDB 配置、复制集、生产数据或基础设施。若需要切换拓扑，应另做备份、维护窗口及授权方案。
- 不允许长期混跑旧版任务派发/服务关联进程；发布前需停止旧进程。新屏障不能约束绕过应用的直接数据库写入或旧代码。
- 运行中同步超过15分钟仍进规划师工作台，但时间本身不是旧进程停止的证明。本轮不提供自动抢占；管理员须确认旧尝试对应进程已结束，再按具体记录的尝试ID/状态条件恢复。不得批量清空所有 running。当前无自助“强制解锁”入口；这类进程崩溃恢复仍是上线验收项。
- 需要真实 MongoDB 验证：双任务成功提交、第二条/最终写失败回滚、并发执行/关联冲突、重复请求、提交结果不明恢复；再做规划师→顾问→健管和客户查看日期的多岗位验收。
- App/小程序读取原任务日期，不新增客户任务或要求重新确认整个年度方案；冻结方案原日期仍作为历史展示。两端日期展示尚未做浏览器/真机端到端验收。
