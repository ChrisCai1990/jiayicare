# 嘉医汇客户消息的企业微信员工提醒

范围：客户在嘉医汇 App／小程序内通过 `POST /api/messages` 发给健康顾问、健管专员、健康规划师、营养师或就医专员的消息。企业微信客户群和微信客服消息不走此入口。

医护员工绑定：登录医护端，进入“个人中心 → 企业微信消息提醒”，生成仅供本人使用的 10 分钟口令；在企业微信工作台打开嘉医汇自建应用，将完整口令作为文字消息发送给应用，看到“员工账号已绑定”后回医护端刷新状态。企业微信管理员还需将该应用设为员工可见。绑定只关联本人账号，提醒仅按客户当前负责岗位发送。

解绑：员工可在医护端“个人中心 → 企业微信消息提醒”查看当前企微账号并解除本人绑定；机构超级管理员可在 Admin“员工管理”搜索员工，查看“企业微信”列并解除该员工的错误绑定。两处都需确认当前显示的企微账号；若绑定已变化，接口拒绝旧页面的解绑并提示刷新。解除后停止该员工的企微提醒，不删除医护账号、客户消息或历史投递记录，员工以后可重新生成口令绑定本人企微账号。解绑记录保留操作者和时间。

## 行为

- 客户消息先保存为 `Message`，再以消息 ID 入队；入队失败不把已保存的客户消息误报为发送失败。后台每 10 秒补扫启用时间后的未入队消息并处理队列。
- 发送前重新读取消息、客户归属、员工状态、机构和企业微信绑定。客户已被医护读取、消息已撤回、人员不匹配或未绑定时跳过，不发送给其他员工兜底。
- 企业微信通知只含“您有一条新的客户消息”和医护端消息页链接，不含姓名、电话、消息原文或附件。点击链接仍需医护端登录，登录后打开“用户留言”页签。
- 同一员工、同一会话一分钟内发送过通知时，后续消息只留队列记录，不重复打扰。提醒的 `sent` 表示企业微信接口接受，不等于员工已读。
- 发送前先持久标记 `sending`。若进程在调用企业微信时中断，或发送结果不明确，不自动重发，以免重复通知；`sending` 和 `failed` 记录供运维核查。网页中的原消息始终保留。

## 启用与验收

默认关闭。生产只在新代码及 `WecomMessageAlert` 的唯一索引建立后配置：

```
WECOM_MESSAGE_ALERTS_ENABLED=true
WECOM_MESSAGE_ALERTS_START_AT=<上线时刻的 ISO 8601 UTC 时间>
```

复用已配置的 `WECOM_CORP_ID`、`WECOM_APP_SECRET`、`WECOM_AGENT_ID`、`WECOM_SIDEBAR_ORIGIN`；后者须为医护端 HTTPS 来源。`START_AT` 是防止上线后向历史未读消息补发的边界，必须在启用前填写。

先用已绑定企微账号的测试医护人员和测试客户，在 App／小程序分别发送文字及图片消息，验证企业微信手机端收到无客户资料的提醒，点击后登录并进入用户留言；再验证错误岗位、跨机构、已读、撤回、未绑定账号不会发给他人。同一会话连续发送两条，只收到一条通知。检查 `WecomMessageAlert` 中的 `sent`、`skipped`、`failed` 和长期 `sending` 数量，确认实际企微设备通知权限。此变更本身不启用生产开关、不发送真实通知。
