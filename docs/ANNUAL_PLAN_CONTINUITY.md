# 年度总评与下一年度方案衔接（2026-09-19，功能分支）

## 本轮能力

1. 阶段评估页增加“生成年度总评草稿”，仅绑定健康顾问/超管可发起，使用 Admin 启用的年度模板。总评固定综合领域，进入顾问工作台审核，沿用归档失败恢复链路。
2. 到期口径改为年度方案确认后进入第 11 个月（满 10 个月）。同一方案的总评周期固定 `Y1`，不因过去两年继续产生 `Y2/Y3`。当前去重仍按方案、模板、周期，跨模板并发保障待补。
3. 下一年度准备清单查询目标年份之前最近一份已确认方案。存在时进入续年路径，必须找到该方案对应、综合领域、年度模板、顾问已审核、已完成归档且档案实际存在的总评。
4. 首次方案仍要求专业评估领域和对应已审核意见。续年不强制重复首次会诊，顾问可按需指定补充领域；指定后仍必须有有效且已审核的专业评估，可采用年度输入或专项协作意见。总评不可通过豁免跳过。
5. 下一年度 AI 草稿把总评作为主评估，并结合最新已审核资料，不照搬已完成任务。响应返回总评来源；草稿保存持久记录 `continuitySource`，发布再次核对。来源变更需重新核对，不能静默替换。
6. 员工端区分首次/下一年度准备清单，可查看已审核总评及进入评估页面。生成、准备确认、保存、推送均核验客户可见范围。

## 保留边界

- **尚未部署**，未修改真实客户、历史方案、启用模板或调度开关。自动评估扫描仍默认关闭。
- 本轮完成的是“顾问发起年度总评 → 审核归档 → 续年准备 → 顾问发起 AI 草稿”的引用与门槛，不是无人值守生成/发布。草稿仍由顾问审核，既有客户确认冻结机制不变。
- 年度方案的 `year` 仍为旧系统年度键，尚未升级为合同/服务周期 ID。总评以方案确认日暂作起点；续约记录、服务期起止、年末跨年/中断续约/变更服务包必须另行建模验收。
- 未实现“续约确认后自动激活下一年度任务”，也未批量开启第 11 个月总评自动生成。不得把提前准备的下一年度草稿视为服务已续约；生产启用前需补激活门槛、日期排期和原年度未完事项处理。
- 上下文仍有条数上限，365 天窗口不是完整全年统计。待补全年聚合、资料覆盖率、缺口说明和来源完整性。
- 旧总评若没有新领域/顾问终审/归档关联字段，不自动视为有效续年依据；旧草稿缺来源时需重新核对，未执行历史迁移。
- 已启用的 Admin 模板不会被启动脚本覆盖。部署前需人工核对模板文案与新触发口径是否一致。
- 首次、续年数据准备中的资料充分性仍由健康顾问确认；不会自动诊疗、处方或改动已有医疗建议。
