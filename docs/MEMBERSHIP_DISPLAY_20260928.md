# 会员权益展示与基金资格修复

## 服务体系与基金分页（本地待部署）

- 服务分为了解健康、持续管理、就医支持，用户明确确认展示口径：AI健康趋势分析每个会员服务期1次；健康档案更新与管理实时；健康咨询、就医规划、专家约诊（不指定）、报告解读服务期内不限次。仅对原计划已包含服务展示，不新增授予。
- 阶段性评估沿用计划配置的每两周/月/季度，未配置时标注按计划阶段安排。月度服务回顾仅医护端展示，客户页面隐藏此内部工作项。
- 用户端与小程序提供健康服务/健康基金/赠送权益切换。基金收支每页5条，保留原接口最近最多100条范围并明确提示；不是全历史服务端分页。刷新成功重置第一页。
- 本轮为展示修改，不新增AI一次额度扣减机制，不将无台账的历史服务次数视为未使用，不修改余额或核销规则。

## 展示优化（本地，尚未部署）

三端统一计划卡、健康管理标签、服务共用额度、独立次数及可展开使用记录。后端只新增结构化 groups 展示字段，保留原 items 兼容旧客户端；不改变资格、金额、核销及历史数据。共用池只呈现一次，所属服务列在卡片内；无历史台账继续标注待核对。8 项权益/三端组件渲染测试通过，最终构建结果见执行记录。

- 用户端、小程序会员权益页和医护客户消费页共用会员权益摘要。有效台账优先，保留冻结权益；共享池只计算一次，用户仅见本人使用记录。
- 无台账的历史会员读取明确配置且有效的服务包，展示计划内容；历史已用/剩余次数标为待核对，不创建或补发次数。

- 发布仅代码，使用 scripts/deploy.py --skip-data-migrations，不修改客户余额、分层、合同及历史使用数据。不扩大试点名单。
