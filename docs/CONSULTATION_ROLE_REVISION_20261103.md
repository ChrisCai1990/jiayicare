# 专家咨询与 MDT 分工修订

本轮代码已修改并通过隔离验证，尚未部署；小程序文案未上传提审。

- 医护端发起：直接沿用客户所属健管专员，进入资料收集；不经过规划师首次派单。所属专员异常时提示修正客户归属，不创建待派单事项。
- 商城发起：规划师首次派给健管专员，此后保持进度查看与督导。
- 健管专员：收集资料、协调已确认专家的时间、占用排班并派发、维护会议链接、拟随访计划。
- 健康顾问：审核资料、关联原转介信、确认专家、参与 MDT、协调意见及审核随访。
- 更换专家由专员说明缘由并退回顾问确认。修改需求或转介会清除先前专家确认，不能绕过确认直接预约。
- 单次咨询预约要求专员覆盖咨询时段；MDT 要求顾问覆盖所有专家参与时段。原冲突检查和预约失败回滚保留。
- 历史医护端待派单且已有专员的事项只读展示为资料收集，专员可以继续提交；不批量迁移历史记录。

验证：隔离 Mongo 完整单次/MDT 流程、角色越权拒绝、顾问重新确认、历史医护端兼容及原转介关联测试均通过（2 项集成测试）；医护端生产构建通过。没有使用真实客户测试，没有修改生产数据。

验收建议：先从医护端客户发起一条单次咨询，依次以专员、顾问、专员、专家、顾问、专员、顾问完成闭环；再测试 MDT 与商城首次派单分支。腾讯会议自动创建仍未接入。
