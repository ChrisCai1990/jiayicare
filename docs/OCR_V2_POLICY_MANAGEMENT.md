# OCR v2 人工标准与提示词管理

## 服务器影子测试开关

OCR v2 在服务器上默认关闭。普通报告继续使用原有解析逻辑，只有显式配置后才启用：

医护端报告列表提供独立的 `OCR v2（测试）` 按钮。原 `AI解析` 按钮会明确传递 `legacy`，测试按钮明确传递 `v2`，每次只影响当前报告，无需修改服务器环境变量或重启服务。两种模式最终都进入人工待审核状态。

已审核报告显示 `重新用 OCR v2`。操作前必须二次确认；确认后清除当前审核状态并重新进入待审核，原始PDF不变。后端同时要求显式确认参数，避免绕过前端误触发已审核报告重跑。

- `OCR_V2_REPORT_IDS`：逗号分隔的 `MedicalReport` ID，仅让指定测试报告进入 v2，首轮服务器测试优先使用。
- `OCR_V2_ENABLED=true`：让全部报告进入 v2；金标准回归和分阶段放量通过前不得启用。

白名单报告仍进入原有 `pending` 人工待审核状态，不会因为质量层判定为 `auto` 就自动审核通过。

## 目标

保留现有人工审核标准，但不再把每一个新增案例直接追加到通用视觉模型提示词。OCR v2 的自动化只生成草稿，医疗含义与最终写入仍由医护审核确认。

## 规则归属

| 新发现的问题 | 应放的位置 | 示例 |
|---|---|---|
| 原图必须逐字抄录、不得推断 | 模型提取契约 | 不补全、不过度翻译 |
| 数值是否落在参考范围内 | 程序校验 | BMI、血压、血常规 |
| 某机构固定版式和预期栏目 | 模板配置 | 爱康/美年/浙一的页码和栏目 |
| 正常完整项是否折叠 | 审核策略 | 只默认展示异常、冲突、缺失、重复 |
| 医护修正的真实错误 | 反馈日志 + 回归测试 | OCR 数值错位、单位漏提、跨页重复 |

## 现有人工标准的迁移方式

1. 现有 `REPORT_PARSE_PROMPT` 不删除，作为兼容基线；其版本由 `backend/src/config/ocrPolicy.js` 标记。
2. 新规则先记录为一个带来源报告和人工确认人的规则卡。
3. 规则卡先判断归属：模型、程序、模板或审核策略。
4. 只有“所有版式都需要的原文抄录规则”才进入简短模型契约；优先写成程序校验或模板规则。
5. 每条规则必须有至少一个脱敏回归样本，不能凭单次模型表现永久加入。

## 灰度与验收

- 新报告使用 `ocrVersion=v2.0`；历史报告不重跑、不覆盖。
- 模板先以候选状态运行，必须用人工审核的脱敏样本核验后才允许减少视觉模型调用。
- 观察字段漏项率、数值/单位/范围准确率、跨页重复率、例外项比例、每份报告审核时间和模型调用次数。
- 任何高风险字段、异常项、字段冲突、低置信项都不得自动写入专项筛查。
