# 年度周期服务的续期门槛（功能分支，2026-09-19）

## 本轮范围

- `annualPeriodicGate` 同时校验客户归属、可信服务权益和来源年度方案的执行门槛。有效续约不再被档案旧到期日拦截；失效、断档、到期或退款不得借档案日期继续启动新周期。
- 首次/历史年度在旧服务期内保留原路径；进入有效可信续年期后，旧年度不得借下一年度权益无限启动周期。续年来源必须自身已经审核、发布、客户确认并进入其合同服务期。
- 自动阶段评估使用此门槛，仍要求试点开关及有效结束日期。年度总评从执行起点（确认日与合同开始日较晚者）计算，不因提前确认而提前触发；证据快照里的原确认时间不被修改。
- 同一评估周期已存在时不再调用AI；单客户凭据查询失败仅跳过该客户并记日志，不默认放行，也不阻断后续客户。
- 年度来源补给只在新周期启动前检查，到期日也必须处于来源服务窗口内，避免服务结束前提前派发越界周期。无年度来源的独立订单/人工补给不增加年度方案门槛。
- 不改已开始的履约流程；旧版已派待办仍可升级到既有履约链。人工暂停/停用不恢复，原记录、日期、审核及任务不删除。
- 不新增人工待办、计时器或AI调用点；沿用原24小时扫描。阶段评估自动扫描仍默认关闭，开启后实际生成草稿仍会使用AI，门槛核验本身不调用AI。

## 验证与限制

332项相关回归通过，包含16项新门槛/调度测试及原阶段评估、供应履约、年度续约、随访、监测和支付链路。测试为模拟数据库/本地HTTP，不连接真实AI或生产数据；本轮没有前端改动。未部署。

未完成项：

- 后续业务已确认更正权限；申请/审核阶段已实现，安全应用未开放，详见 `ANNUAL_SERVICE_PERIOD_CORRECTIONS.md`。生效凭据仍不可直接覆盖。
- 手动阶段评估生成入口、强化营养等其他周期入口尚未统一接入本门槛；不要称为所有周期服务已经统一。
- 自动阶段评估既有最近500份方案上限、大规模扫描、跨进程同时生成AI评估/补给周期的并发幂等仍需专项处理；本轮测试只保证顺序重复扫描不重复生成。
- 不取消退款前已产生的任务，不自动决定退款后已启动服务如何结算；故障记日志，未新增周期扫描异常工作台队列。
- 真实MongoDB索引/并发及多岗位端到端仍待验收。
