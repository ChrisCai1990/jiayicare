# 新增协作事项的责任异常兜底（2026-10-01）

前三批新增的服务建议跟进、营养聊天异常、方案修订执行核对已有业务待办，但原 workbenchAssignmentAttention 未检查这些来源的负责人。会员缺少、停用或错误配置负责人时，管理员缺少统一修正提示。

本批接入原管理员异常列表，沿用按会员和岗位合并的标识、文案及会员归属入口：

- 年度服务建议：仅原规则可处理的客户求助或显式开启且到期的建议；拒绝、已处理、未来、草稿、无效日期格式及孤立/跨会员方案引用排除。
- 方案执行核对：仅 applied + executionReview.version=1 + pending，同一方案一项；旧记录不回填。
- 营养聊天：failed 或运行/保存中已过期的异常；正常运行和已结束排除。

三个来源均经本机构未删除会员集合限制；AnnualPlan/AnnualServiceRecommendation 没有 tenantId 字段，不能直接加该字段造成合法非空机构全部漏查。检查负责人仍要求同机构、在岗、对应岗位。岗位归属修正或来源处理后，下一次原工作台读取自动退出异常。

仅超管看到归属修正异常；健康规划师、顾问、健管、营养师不增加管理员任务。不新建记录、不修改原来源、不自动改派，不调用AI、发消息或改变自动化开关。

验证：独立 localhost:27964 随机 MongoDB 库，真实查询覆盖多来源合并、零写入、缺失/停用/错岗/跨机构人员、机构/已删除隔离、旧记录/未来/孤立来源、已处理退出、正常运行及四岗排除。结合原责任异常、日期提醒和执行核对规则，共20项通过，无跳过。无前端改动，按标准后端发布流程同步最新master并跳过数据迁移，实际结果见外层 tmp/assignment-handoff-deploy.log。
