# 阶段评估岗位分流（2026-09-19，功能分支）

## 已实现

- 新综合健康评估直接进入客户健康顾问工作台；营养、运动、药食同源分别进入已分配的专业人员工作台。缺少人员不调用 AI。
- 风险或主动升级转健康顾问；退回仍回原专业。综合评估退回由顾问重新生成，不转营养师。旧记录无领域字段时保留营养审核，不批量迁移。
- 员工端选择领域，后端独立核验客户归属、当前岗位和版本。乐观锁防旧页面覆盖；风险检测使用实际审核内容。
- 常规手动生成使用启用的季度模板；强化营养保留原 12 周节点。季度默认近 90 天，年度 365 天，强化营养 7/14 天窗口。
- 同方案、模板、周期、领域去重；旧周期无领域后缀时不重复生成。
- 自动扫描由每小时改为每 24 小时，启动时检查一次；只处理试点且服务期有效、未删除客户的最新已确认方案，扫描季度/年度模板。查询不调用 AI，实际生成才调用。
- 只改员工端和后端，不改变客户首页、用药录入及既有服务执行流程。
- 归档恢复：审核快照先保存为 `archive_pending`，写档成功才标记 `finalized`。异常或进程中断后仍在最终审核岗位工作台；同岗现任人员可一键重试，无需 AI 或重新审核。重试忽略客户端修改内容，保留原审核人，另记恢复操作人。按来源唯一键只插入一次档案，迟到失败不降级已完成状态。
- 工作台定位支持读取最近 20 条之外的指定评估，并切换到对应常规/强化模式；后端仍限定客户归属。

## 未完成与上线边界

**未部署；自动开关默认关闭，不是全量自动化上线。** 只有 `ENABLE_PHASE_ASSESSMENT_SCHEDULER=true` 才运行；客户需 `aiPilotFeatures.stageAssessment=true`，模板需 Admin 审核启用。本轮未修改真实客户或模板配置。

启用前须处理：

1. 生成持久队列、并发占用及失败补偿。查询后调用 AI 的多进程竞争仍可能重复消耗 Token；唯一索引仅防重复写入。
2. 扫描分页（当前最多 500 条方案）、重复适用模板选择、人员缺失提示、服务期续约联调。
3. 历史归档核验：新审核已具备待归档恢复，但旧版已标记 `finalized` 而缺档的历史记录未批量扫描或迁移；需另行只读核验、确定范围后修复。当前恢复为异常待办一键重试，尚无自动后台重试队列。
4. 月度自动资料回顾、通用双周/月度强化配置、事件评估、跨学科会签、复评建议自动转随访尚未形成完整能力。
5. 年度总评到下一年度正式草稿未接通。年度模板沿用确认日满 11 个月触发，与业务“第 11 个月”起点须在年度衔接时统一。
6. 上下文有条数上限（健康记录 240、随访 60 等）；365 天窗口不等于全年完整统计，须补聚合、覆盖率及缺口标记。

药食同源仅健康管理、档案承载，不诊疗、处方、辨证施治或承诺疗效；提示词边界不替代人工审核。
