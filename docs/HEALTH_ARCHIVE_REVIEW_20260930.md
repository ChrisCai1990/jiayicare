# 健康资料结构与初次建档复核

## 已确认行为

- 健康资料按健康基础与生活方式、不适主诉与症状、用药与营养补充剂、专项筛查与评估、原始资料、健康画像排序。专项研判与 AI 健康信息整理同层；体检关键指标、身体成分评估在筛查结果页依次展示。
- 基础档案独立展示家族史、疾病史与当前状态、过敏史与不良反应史；症状页区分当前与既往记录。可后续补充，原修改记录保留。疾病状态支持逆转、复发及变化时间；逆转必须填写时间与依据，不自动推断。
- 用药与营养补充剂沿用原 Medication / Supplement 记录及专业审核；基础档案只读取当前摘要，不增加第二套产品记录。问卷粗略自述保留供人工核实。
- 初始录入入口移入健康监测，改名健康监测数据补录，保留用户端同步及批量导入。
- 首次健康问卷（现有成人健康问卷或映射至少三个核心板块的问卷）的首次答卷，空档案字段直接写入；已有人工值不覆盖，原回答保留在复核来源中。后续答卷仍走原变化核对，不重启初次任务。膳食及心理问卷的专属审核保持。
- 同一客户的初次建档任务复用 archive_review 工作台类别，包含六个板块。工作人员需逐项勾选已核实的问卷内容并填写核实依据；四个核心档案先补全或明确标记无相关情况／不详。六板块全部完成才结束。初次期间修改已核实核心板块会重新置为待核实；完成后常规追加不重新开启初次任务。
- 问卷写入并发冲突保留原答卷并提示工作台重试。数据写入使用字段白名单、负责人范围与编辑权限、版本比较和原子条件更新，防止覆盖其他人员刚保存的记录。

## 数据与接口

User 新增 coreHealthArchive、coreHealthArchiveHistory、initialArchiveReview、initialArchiveReviewHistory、initialArchiveImportPending。旧健康档案摘要作为兼容投影给现有画像与分析读取；来源问卷不修改。新档案保存后，旧员工端摘要编辑不能覆盖已经建立的核心记录。

- PUT /api/staff/patients/:id/core-health-archive/:section
- PUT /api/staff/patients/:id/initial-archive-review/:section
- POST /api/staff/patients/:id/initial-archive-review/retry

App 与小程序共用问卷提交接口，问卷题型和客户端接口保持兼容，无需重新上传小程序。详细核实操作仅在员工端提供。已存在客户的历史问卷与病史保留，不批量迁移或自动创建历史复核任务；健康评分所用慢病分级仍由原流程维护，不由“逆转”标签自动修改。
