## 结构变更审核范围

以最终模型为准，以下不是可直接执行的迁移脚本：

| 模型 | 重点约束 |
|---|---|
| FollowUp、Task、RecurringSupplyPlan等派发目标 | annualDispatchKey唯一稀疏；FollowUp还需assessmentActionKey |
| CheckupPreparationHandoff | servicePlanId唯一；运行时仅核验 |
| CheckupPreparationSuggestion | 独立集合、方案_id占用与状态兼容 |
| AnnualServicePeriod | sourceOrderId部分唯一、evidenceOrderIds稀疏唯一、线下合同组合唯一 |
| FollowUpServiceLink | requestTaskId与followUpId分别唯一 |
| ProfessionalHealthAssessment / ReportFollowUpDraft | sourceFeedbackKey / sourceKey来源幂等 |
| AnnualPlanPreparation / PhaseAssessment | 客户年度、方案模板周期组合唯一 |

检查重复、显式null、数组/多键和部分过滤语义，再提出逐项建索引方案。不得自动删历史数据、使用syncIndexes删除旧索引或回填历史派发标记。生产standalone不支持多文档事务，已派发改期保持受限；架构升级单独审批。

## 授权顺序

1. 当前仅隔离测试和本清单，无生产写入。
2. 完成只读结构审计及启动副作用控制后，提交准确迁移/部署命令、影响与回退方案供批准。
3. 批准后备份、执行批准的结构变更与部署，新增派发保持关闭；核对API、各端、旧业务及后台日志。
4. 多岗位验收通过后单独批准启用。全局开关不是客户白名单；若限定客户，须先实现并验证限定措施。
5. 历史已确认方案不回填。真实客户按真实业务执行，不改日期制造窗口、不造报告或订单；小程序变更单独构建、提审、发布。

## 停止与回退

- 重复派发、跨客户关联、越权、异常扣次、误通知或旧流程回归时停止扩大，暂停相关入口/后台任务。关闭体检开关不撤销已有任务。
- 保留日志和审计/来源凭据，核对业务副作用，不批量删任务或重开。
- 使用经审核回退提交/原产物及配置，先验证旧代码兼容新数据；保留索引及完成凭据。不可用旧数据库快照覆盖期间真实业务。
- 数据修复、客户沟通及必要的数据库恢复独立审批，并明确增量保留方案。

结论：局部数据库验证通过，不等于生产全链路闭环，尚不具备直接上线条件。
