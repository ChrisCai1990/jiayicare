# 就医安排与健管报告承接

- 就医专员完成后，upload 环节由本次健管专员承接，audit 继续由健管专员办理。报告逐份审核门槛、顾问终审及年度原文保留不变。
- 健管工作台读取时仅核对本人、同租户、白名单内 upload/audit 流程的活动任务。旧 upload 负责人修正记录系统交接事件，不批量改写历史。
- 健管可关联本客户既有报告（包括客户上传），也可代上传；资料必须属于同客户同租户。选取报告保留在交接事件中，审核通过前不能进入随访草稿。
- 客户健康计划从同一流程实际预约结果只读投影，不创建可人工勾选完成的重复任务。不显示内部研判、派单备注及统筹任务。已关联具体安排的旧随访提醒在客户侧去重。
- 客户从健康计划进入既有报告上传入口；健管确认与本次事项的关联，避免猜测报告归属。
- 缺少检查预约日期的显示待安排，不能把门诊日期当检查日期。取消项不产生客户检查计划。
- 原年度启动任务保留数据库历史但退出客户任务列表；原年度方案与通知入口保留。
- 本次仍沿用既有白名单，代码发布跳过数据迁移；不代办真实业务或生成临床结论。

验证：47 项定向回归通过；部署版本和最终构建结果以发布日志为准。
