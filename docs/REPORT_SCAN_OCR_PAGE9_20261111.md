# 扫描检验页离线 OCR 补提（2026-11-11）

## 问题与处理

既有年度报告第 9 页是无 PDF 文字层的扫描检验表，草稿为 0 项；单页补提固定预留 4 次视觉模型调用，而该页只余 2 次，所以在识别前被预算保护拒绝。提高额度只会重试此前易超时、易截断的整页视觉路径。

本改动为无文字层的年度报告双栏检验页增加离线 OCR 路径：先识别页面左右两个数值列，再分别识别左右栏，按物理行与栏目配对。运行环境使用独立目录中的 RapidOCR 3.10.0 和 ONNX Runtime 1.31.1，不调用外部模型，不消耗 AI 页级调用次数。仅当页面检测到明显双数值列且形成至少 6 条候选时使用；其他版式回到既有补提路径。

OCR 条目仅进入 **待人工核对** 的报告草稿，保留原报告页码、栏目、行序和参考范围。原有人工已核对项目不被覆盖；同名但位于不同栏目且结果不同的两条原文可分别保留。审核窗在补提结束后刷新并显示“待核对”，不将 OCR 候选称为已核实。

## 限定授权样本的离线对照

对已授权的 2023 年第 9 页临时原图：Tesseract 双栏识别有项目名乱码及错误数值；RapidOCR 离线模型在 300 DPI 下检测到 182 个全文框，左右栏单独识别生成 193 个框。坐标解析得到 51 条候选，与原图可见约 51 条结果的数量相符；49 条带参考范围，2 条含明确异常标记。一次本机完整 CLI 处理约 35 秒；服务器隔离试跑全文 OCR 约 20 秒、峰值常驻内存约 562 MiB。数量匹配不等于全部字段临床准确，所有候选仍需医护逐行核对，特别是跨行名称、参考范围和异常标记。

本次真实页只读试验不修改患者报告或 AI 额度。原图、词坐标和含原文的 JSON 仅在临时目录保存，试验完成删除；仓库只保留脱敏统计与合成测试。

## 发布条件

1. 在生产代码之外的独立工作树构建医护端，运行后端与合成表格测试，并用指定页只读验证 CLI、Node 桥接和 51 条候选。
2. 将锁定的 Python 包安装在 `backend/.ocr-runtime/site`，不修改系统 Python 或现有 Node 依赖。发布代码时跳过数据迁移，保护线上未提交内容。
3. 发布后只检查服务健康、运行时可用性与报告原有状态；已有报告不会自动改写。医护在原审核窗口点击“补提第 9 页”后才生成待核对草稿。
4. 如 OCR 条目或栏目有错，停止该页审核并按原图修正；禁用该运行时目录即可回退到原有 AI 补提路径。扫描检查、处方、病历以及其他版式需独立验收。
