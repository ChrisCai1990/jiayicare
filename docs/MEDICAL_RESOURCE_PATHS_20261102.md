# 就医资源两条维护路径（2026-11-02）

## Admin 与后端

- **按问题找就医资源**：用疾病、症状或服务场景查推荐医院、科室、专家及推荐依据。沿用 `MedicalResourceKnowledge` 的优势科室、专家推荐、就诊注意事项和服务案例类型。
- **按医院找预约联系方式**：用医院、院区、普通/专家/国际门诊或体检类型查官方平台、医院预约电话、内部联络方式和具体步骤。沿用 `appointment_rule` 类型，新增结构化预约字段，不复制医院、科室基础档案。
- 两条路径在 Admin 与医护端各自分入口，并通过 `path=problem|contact` 分别检索。医护端仍只读取已发布且未过期的条目；联系资料按医院、院区和预约方式展示。
- 联系方式可保存草稿；送审前必须有关联医院、服务类型、至少一种预约渠道，以及核实日期、来源/核实人和未来复核日期。发布、归档、修订和旧方案引用快照沿用现有流程。
- 已发布的旧 `appointment_rule` 条目继续展示，不自动补造电话、服务类型或核实记录；归档后可生成修订草稿，补齐字段再送审。
- 原问题就医条目中的旧预约说明仍可在医护端折叠查看，并提示再次核实；新问题就医草稿不再自动写入通用预约话术。

## 预约联系方式简化（2026-11-02）

- Admin 首屏只填医院、预约类型、院区、医院电话、医院邮箱和已确认的官方平台；其余字段收在“更多信息与发布核实”。显示名称留空时按医院、院区和预约类型生成。
- 一院区一条记录。电话保留录入原文，不自动补区号；医院邮箱独立存储、检索，并在医护端展示。
- 草稿可先保存联系方式；送审前仍需实际核实日期、来源/核实人和未来复核日期。本次代码发布不自动创建或发布医院联系资料。

## 范围与验证

本批不改生产业务数据、不迁移旧条目、不自动发布，也不代表医院电话已由人工核实。定向测试覆盖路径分流和联系方式送审校验。Admin 构建须在具备依赖的环境执行后再发布。
