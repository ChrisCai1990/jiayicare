# 功能医学人工审核流程

2026-09-13：补齐此前仅拦截后端解析、遗漏上传状态和医护界面的问题。

- 统一按 `type=functional/home_monitor` 或 `documentCategory=functional_medicine` 判断人工审核资料；不以标题猜测覆盖人工分类。
- 新建和后续保存时，未审核的 `none/failed` 记录进入 `pending`，解析任务标记 `skipped`；已审核、已驳回、已有项目不被重置。
- 历史 `none/failed` 记录无需批量更新，列表和待办查询按分类直接呈现人工审核；列表筛选计入“待审核”，排除“待解析”。
- 资料详情允许直接人工审核；存在历史提取项目时仍可“核对已有数据”。不再要求先调用 AI。审核通过仍走现有权限和正式审核接口。
- 首页排除人工资料的解析待办，使用“功能医学待人工审核”和原件核对说明，保持当前员工客户范围；已审核和已驳回不再进入待办。
- 历史结果编辑页隐藏单页补提；单页补提接口和执行器同样禁止人工资料调用模型。
- 医护端和用户端解析接口共用禁止解析策略。用户端新建报告共用模型初始化；本次网页发布不包含小程序客户端提审发布。

## 验证与发布边界

- 相关 16 项后端测试通过，医护端生产构建通过。
- 使用虚构报告和拦截 API 的浏览器验证：旧 none、新 pending 功能医学均显示人工审核；普通年度体检保持 AI 解析；详情人工审核入口可见、无 AI 确认前置提示；页面无 JS 错误。
