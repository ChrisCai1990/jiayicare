# 按人员设置佣金：验收设计与业务归属核对

日期：2026-11-12。本文是管理端和结算改造的设计稿，尚未表示页面或新规则已经发布。

## 一、管理端只保留一个佣金规则入口

入口：管理后台 → 佣金规则。顶部切换「员工」「市场合伙人」，两类人员沿用同一张简洁表单：

1. 搜索并选择一个人。
2. 选择一个业务类别。显示该类全部在售商品及收费规格；支持搜索、全选、逐项勾选。365 服务包也作为可选项目列出。
3. 对勾选项目填写一套推广比例；员工可再填写服务比例。年度类别可填写首年、第 2 年、第 3～5 年比例，之后默认为 0。单次类别可选仅首次或每次，不能暗中改变已有合同约定。
4. 页面下方只显示「适用项目数、比例、生效时间」摘要和一笔金额试算。点击保存后创建新版本，对新订单生效；旧订单按原规则版本结算。历史版本默认收起，仍可查阅。

同一人某类项目共用一套规则。确实有例外时，在「例外项目」中搜索并单独设置，默认不展开。一个项目对同一人同一角色同一时间只能命中一条规则；例外优先于类别规则。员工规则和合伙人规则分别计提，不把同一位推荐人重复记为内外两种推广来源。

## 二、账务口径

- **业务归属**：继续由产品库或年度服务包维护服务、产品、资源的金额拆分，合计订单净实收的 100%。这只是团队业务量，不自动发给个人。
- **推广佣金**：按订单确认的推荐人及其个人规则，以核实后的现金净实收计算。年度首续次数按现有已核准服务年序处理；单次规则遵守仅首次／每次的明确配置。
- **服务佣金**：仅员工实际执行并有履约／核销证据后计提；组合项目按对应子项目净实收份额计算，不把整单金额重复作为多个岗位的基数。
- **企业资源**：只记业务归属，不关联人员，也不自动产生推广或服务佣金。
- **退款与调整**：订单保留所用规则版本和基数快照；退款生成差额及追回待办，规则修改不重算旧订单。后台逐单显示规则版本、归属金额、推广费、服务费、已发和待发。

现有代码中的员工个人比例、多岗位服务比例、产品指定员工覆盖和合伙人逐商品规则尚未统一成上述优先级。改造时须迁移为兼容兜底，不能仅隐藏旧页面；新规则未配置时仍可读取历史配置，但同一笔订单不得重复计提。

## 四、验收顺序

1. 管理端按员工及合伙人各配置一人、一类、多项目；搜索、勾选、修改、保存和回显一致。
2. 测试同类别默认规则与一项例外，确保明确的 0% 不会回退到旧产品规则。
3. 用合成订单验证线上、线下、首次、年度续费、多岗位履约、部分退款；逐单推广／服务佣金与规则版本一致。
4. 业务负责人补齐上节 7 个未配置单元后，再核对全量配置覆盖率。

生产现状核对脚本：`scripts/audit_business_attribution_readonly.js`，通过 `scripts/run_business_attribution_audit.py` 只读运行。
