# 企业共享健康基金

## 地芯科技示例的启用顺序

1. 在「企业客户管理 → HR数据」录入该年度**健康管理服务**起止日期。共享基金沿用这段日期，不使用高端险保单日期作为基金期限。
2. 在「高端医疗险」建立生效方案，把员工、配偶、子女分别关联为有效参保人。家属仍需是该企业已关联会员。
3. 在「共享基金」逐项勾选保险方案和可额外购买的健康管理商品，保存规则。默认关闭。
4. 核对实际到账后，用唯一凭证号逐笔登记企业自有或平台赠送金额，再启用。原 HR 手工基金台账只保留历史展示，不会自动转为可支付余额。

客户结算时单独选择「企业共享基金」。服务端验证企业、参保人、保单、健康管理日期、商品白名单和余额；按优惠券后价格的最多 50% 抵扣，其余由客户微信支付。个人健康基金与企业共享基金不能在同一订单叠加。多商品合并付款按每件商品分别计算 50% 上限。

账本按企业和健康管理年度独立保存。预留、入账、支付确认、取消释放、全额退款返还均在单个 MongoDB 文档上以订单 ID 或入账凭证号条件更新，重复回调不会重复移动金额。支付状态待确认时保留预留，待确认关闭后才能释放。管理员可在「共享基金 → 核对订单账本」修复订单和账本之间的中断状态。到期不再提供新抵扣，剩余金额仍保留用于对账。

HR 端只显示累计入账、可用、待支付预留和已使用的汇总，不展示个人订单或参保身份。当前既有 HR 看板的手工数据与实时共享基金分开展示。

## 发布边界

后端和 Admin 随常规部署发布；微信小程序需要另外上传、提审并由人工发布，因此后台部署后，小程序用户不一定立即看到新结算开关。App 当前原生商城未接真实支付完成确认，暂不展示新的共享基金开关，避免创建无法完成付款的基金预留；App 支付链路接通后应使用同一服务端规则。配置与入账均默认不自动执行。若示例年度的健康管理服务已经结束，客户端不会出现抵扣选项；需要录入新年度有效日期和对应保险方案。
