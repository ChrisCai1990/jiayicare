## 2. 本轮已补齐

- 手动常规、年度总评及强化营养新评估统一调用可信服务期门槛；不允许通过手动入口绕过到期、退款失效、未来服务期或旧年度限制，管理员亦不绕过。
- 年度总评按有效执行起点进入第11个月，不以提前确认日期提前触发；该起点同时传给评估生成器。
- 未来开始、无效开始或已结束的强化营养方案不误判为第1周。有效方案保留原12周节点和营养岗位。
- 既有评估的查看、审核、退回和归档不加新周期门槛；本轮不启用自动扫描、不调用真实AI、不增加客户任务。

验证：397项相关回归通过，其中新增8项手动入口测试；使用模拟数据库和本地HTTP，未调用真实AI。此轮无前端改动，未重新构建员工端；上一轮构建通过不替代多岗位浏览器验收。生产核查仅为下述只读元数据检查，不是新功能在生产的验收。

## 4. 收尾顺序

1. 补年度体检前14天两岗位并行准备，复用现有预约/执行链，不重复创建服务或收费订单。
2. 补阶段评估持久生成队列与并发去重、失败恢复和扫描覆盖；再决定何时开启试点。随后按已确认蓝图补通用强化、事件评估和复评建议承接。
3. 核验用药资料准备门槛、转介结构化用途与反馈恢复；补全工作台一致性只读审计。
4. 在独立测试数据库验证索引、并发、故障恢复；按下列真实岗位场景验收。未通过不直接全量上线。
5. 输出版本明确的上线/回退清单，由用户确认部署。数据库架构调整另行批准，不与应用发布混为一次默认操作。

## 5. 用户参与的最小验收场景（待技术条件具备后）

1. 首次客户：专业意见未齐不能发布；齐备后顾问确认，固定岗位无需重复选人。
2. 一条就医事项：规划师接服务需求，健管保留督办，服务岗位按流程行动，完成自动回写；另测取消/退回。
3. 后续报告/会诊：只生成顾问待审草稿，确认后新增当次随访，不重建年度方案、不重复派单。
4. 年度体检：前14天两岗位收到各自必要事项，预约前条件汇合，不要求重复“确认完成”。
5. 续年及异常：未核验订单/合同不能启用；续约后正确承接，已完成历史不重开；改期失败不出现半批新日期。
6. 客户侧：血压/体重只作轻提示，无大量逾期任务与未读堆积；员工工作台仅出现本人当前需要处理的事项。
