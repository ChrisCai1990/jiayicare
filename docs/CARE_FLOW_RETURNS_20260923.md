## 边界

- 仅现有健康管理 allowlist 客户的年度单项就医协助；纯提醒不生成协助任务，全托管及已关联旧服务沿用原流程。
- 现有任务打开“进入完整就医流程”后明确接入；不批量迁移历史客户数据、不代客户完成预约或派单。
- 顾问已确认的年度方案和原临床随访内容不被覆盖。修订限本次服务交接副本，原文与前后变化保留。
- 发布保持金娟试点，关闭 recovery/checkup preparation 自动开关，使用 skip-data-migrations。

## 流程与回退

顾问年度交接 → 健管预约 → 规划师派单 → 就医专员执行 → 报告及资料上传 → 健管审核 → 自动随访草稿 → 顾问审核 → 服务结束。

已有预约或已派单的事项从实际阶段接入，不要求重走前置流程。各阶段可退回之前责任环节；必须填写分类、原因。修订必须说明并确认，直接返回发起环节；嵌套回退按栈返回，不重走中间环节。已结束服务不能直接改写。

每次回退保存发起人、接收人、阶段、时间、问题、修订前后内容、修订说明、返回对象、耗时；事件只追加。接收回退不是人员过错判定。顾问修订后必要时要求预约重新核对；上游修改使旧随访草稿失效。

## 安全及一致性

- 机构、参与人、当前阶段角色及负责人校验；乐观版本锁；AI 生成租约；确定性任务 ID 和重复同步保护。
- 接入后旧派单、预约、编辑/删除入口不再允许改写；服务工作台按当前流程序号展示当前任务，原预约任务不重复显示。
- 报告原件追加到既有报告管理，不自动审核。必须逐份完成原报告审核，才能进入草稿生成；失败保留阶段，重试不覆盖新版本。
- 同依据已生成的草稿可复用；最终随访内容、日期由顾问核对。只有顾问通过、正式随访任务同步后显示服务结束。
- Admin “就医协助质量”仅机构 superadmin 访问。统计按接收岗位、人员、问题分类汇总数量、重复次数、修订耗时；只统计接入后的最近更新500项，超出明确标记。复核与优化措施只追加，不自动修改医疗规则。
