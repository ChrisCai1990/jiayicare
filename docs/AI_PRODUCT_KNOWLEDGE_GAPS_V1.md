## 需要业务团队优先确认

### P0：上线 AI 推荐前必须确认

1. **就医陪同服务价格显示异常**：商城 `originalPrice` 为 ¥299，但当前最低售价为 ¥380，容易产生“划线价低于售价”的展示与解释问题。
2. **部分产品只有 `servicePrices`、没有有效 SKU**：轻咨询计划、专家约诊服务、其他城市服务咨询等存在此情况。需明确 AI 和下单流程统一以哪个字段为准。
3. **价格口径**：`originalPrice`、`servicePrices`、`skus`、会员价并存时，必须定义唯一优先级；AI 不应自行选择。
4. **服务地域**：大多数产品 `serviceLocation` 为空，但就医协助高度依赖城市和医院资源。需补充支持城市或“购买前必须人工确认”。
5. **资源结果承诺**：专家约诊、住院、检查和特需服务需明确哪些结果不能保证，以及预约失败如何处理。
6. **全专联合远程会诊**：需确认其合规主体、专家资质、交付形式、用户告知和记录留存要求；AI 只能做服务介绍与需求转交。
7. **企业护航计划中的保险内容**：需确认保险合作主体、销售/转介资质、具体保障不由 AI 解释或承诺。

### P1：影响推荐准确率

1. 为每个产品增加明确的“不适用情况”。
2. 为每个规格增加服务次数、时长、有效期和包含/不包含项目。
3. 补充各产品的购买前必问信息，例如城市、医院、服务对象和预约时间。
4. 明确第三方费用是否包含：挂号费、检查费、药费、快递费、交通费和专家费。
5. 明确取消、改期、退款时点和已开始服务的判断标准。
6. 明确家庭产品覆盖人数、儿童年龄和新增家庭成员规则。
7. 明确体重管理服务的健康筛查、退出标准和不适用人群。
8. 明确心理咨询与心理陪伴的差异、咨询师资质、危机处理流程。

### P2：有助于提高转化率

1. 给每个产品增加 3～5 个真实典型场景。
2. 增加客户最常见顾虑及批准话术。
3. 增加可公开、已获授权且不夸大效果的案例。
4. 增加与相似产品的差异说明，例如“体检一站式服务”与“健康体检服务”。
5. 增加推荐后的标准下一步：直接购买、先咨询、预约评估或转人工。

## 建议新增到 Product 的 AI 字段

以下字段属于运营可维护的产品知识，不宜依靠 AI 从长篇描述中猜测：

```json
{
  "aiProfile": {
    "enabledForRecommendation": true,
    "targetNeeds": [],
    "suitableFor": [],
    "notSuitableFor": [],
    "requiredQuestions": [],
    "supportedCities": [],
    "includedItems": [],
    "excludedItems": [],
    "promiseLimits": [],
    "handoffConditions": [],
    "nextAction": "inquire",
    "operatorNotes": ""
  }
}
```

字段修改后应立即影响后续 AI 推荐，不需要重新训练模型。后台保存产品时，可做完整性校验并提示运营补齐缺失项。

## 动态更新机制

1. 管理后台是产品唯一维护入口。
2. AI 在生成产品推荐前，查询当前 `status: on` 的产品。
3. 使用产品 ID/SKU code 保存推荐，不使用产品名称作为关联键。
4. 推荐页面展示时再次读取实时价格与上架状态。
5. 产品修改后使缓存失效；若使用缓存，建议有效期不超过 5 分钟。
6. 对价格、上下架、规格和服务边界变更保留审计记录。
7. 每日自动检测数据异常：售价高于划线价、无规格、空适用人群、空流程、重复 SKU、缺少服务地域。
