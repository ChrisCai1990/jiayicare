# 多机构开放前隔离验收（2026-10-02）

## 当前结论

生产已将现有客户归入嘉医汇机构，平台账号只能进入机构与全局 AI 预算页面；外部机构创建开关仍关闭。当前代码**尚不具备开放第二家机构的条件**。

## 已确认的缺口

1. `FollowUp`、`PushRecord` 等客户业务模型没有 `tenantId` 和租户查询钩子。部分接口只靠客户 ID、员工 ID 或上层查询约束，尚不能证明全部跨机构读写被拒绝。
2. 医护工作台 `GET /api/staff/...` 直接调用 `FollowUp.collection.find`；原生集合查询绕过 Mongoose 插件。其他医护、用户与问卷路由也有原生 `User.collection` 读写，需要逐条确认目标客户已属于当前机构。
3. 多个推送接口用请求中的 `patientIds` 批量 `PushRecord.insertMany`，未统一验证每位客户的机构。问卷推送还将这些 ID 加入问卷目标客户列表。
4. 静态检查约 101 个模型文件未挂租户钩子；其中含全局配置或系统模型，不能按数量直接认定为漏洞。应先按客户数据、员工数据、机构配置、平台全局配置分类，再逐类迁移和验收。

## 本次代码加固

对已挂 `tenantScopePlugin` 的模型，机构请求无法通过 Mongoose 更新或保存修改 `tenantId`；批量插入会自动标本机构并拒绝外机构归属。专项单测覆盖查询覆盖、更新拒绝与批量插入。

## 开放第二家机构的门槛

1. 给客户业务模型补归属字段和索引，先审计现有集合，再备份、迁移嘉医汇历史数据；旧数据不可因新过滤条件消失。
2. 修复原生集合查询和所有批量推送：按当前机构验证客户 ID，限制查询和写入目标。
3. 在独立测试库建立 A、B 两机构、员工与合成客户，覆盖 Admin、医护、用户端的列表、详情、创建、修改、推送与关联对象；验证跨机构请求均被拒绝且本机构流程可用。
4. 完成应用端验收后，再考虑打开 `ENABLE_EXTERNAL_TENANTS`。在此之前保持关闭。

本次未向生产写入合成客户，也未打开第二机构入口；本文件记录代码检查结果，不代表完整的跨机构验收已经通过。
