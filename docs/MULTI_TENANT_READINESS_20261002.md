# 多机构开放前隔离验收（2026-10-02）

## 当前结论

生产已将现有客户归入嘉医汇机构，平台账号只能进入机构与全局 AI 预算页面；外部机构创建开关仍关闭。当前代码**尚不具备开放第二家机构的条件**。

## 已确认的缺口

1. `FollowUp`、`PushRecord` 的机构字段、查询钩子、客户归属写入校验已在工作分支补齐；生产尚未发布。其他客户业务模型仍有未隔离部分，尚不能证明全部跨机构读写被拒绝。
2. 医护工作台原生 `FollowUp.collection.find` 已在工作分支显式加机构过滤；其他医护、用户与问卷路由也有原生 `User.collection` 读写，需要逐条确认目标客户已属于当前机构。
3. 多个推送接口用请求中的 `patientIds` 批量 `PushRecord.insertMany`。本次已给四个医护推送入口增加本机构客户校验；其他写入 `PushRecord` 的链路仍需逐一审查，问卷目标客户列表也需在合成双机构环境验收。
4. 静态检查约 101 个模型文件未挂租户钩子；其中含全局配置或系统模型，不能按数量直接认定为漏洞。应先按客户数据、员工数据、机构配置、平台全局配置分类，再逐类迁移和验收。

进一步筛选发现，未挂钩子的模型中约 70 个包含客户或会员关联字段，涉及年度方案、消息、用药、支付及服务记录等。开放外部机构前必须完成这些核心链路的归属和越权测试；当前双机构测试只覆盖随访、推送及其鉴权。

## 本次代码加固

对已挂 `tenantScopePlugin` 的模型，机构请求无法通过 Mongoose 更新或保存修改 `tenantId`；批量插入会自动标本机构并拒绝外机构归属。四个医护端批量推送入口会先核对所有目标客户均属本机构。专项单测覆盖查询覆盖、更新拒绝与批量插入；推送入口目前仅完成语法检查，仍待隔离库 HTTP 验收。

2026-10-02 生产只读核查：`followups` 366 条、`pushrecords` 411 条，均未标机构，但每条都关联已归嘉医汇的客户；无孤儿客户、无其他机构归属。工作分支已准备 `assignJiayihuiCareRecordsTenant.js`，要求备份确认及两个集合的预检数量。隔离本地 Mongo 双机构测试通过：A 无法读取/修改 B 记录，跨机构客户写入被拒绝，本机构创建、批量写入、幂等历史归属迁移及医护推送列表 HTTP 验证通过；孤儿客户会阻止迁移。医护与客户鉴权也增加启用机构检查。相关随访专项回归 120 项通过；另有 2 个页面渲染断言、2 个审核路由断言在未改动的主分支同样失败。上述改动尚未发布生产。

发布时必须先暂停写入、取得新备份，重新核对 366/411 是否随业务增长，按当时数量执行迁移，并验证嘉医汇随访及推送页面。部署工具目前先重启后端再执行常规数据迁移，不能直接用于本次带新隔离字段的发布；须安排迁移先于新代码进程启动。旧备份不能替代发布当时备份。

## 开放第二家机构的门槛

1. 给客户业务模型补归属字段和索引，先审计现有集合，再备份、迁移嘉医汇历史数据；旧数据不可因新过滤条件消失。
2. 修复原生集合查询和所有批量推送：按当前机构验证客户 ID，限制查询和写入目标。
3. 在独立测试库建立 A、B 两机构、员工与合成客户，覆盖 Admin、医护、用户端的列表、详情、创建、修改、推送与关联对象；验证跨机构请求均被拒绝且本机构流程可用。
4. 完成应用端验收后，再考虑打开 `ENABLE_EXTERNAL_TENANTS`。在此之前保持关闭。

本次未向生产写入合成客户，也未打开第二机构入口；本文件记录代码检查结果，不代表完整的跨机构验收已经通过。
