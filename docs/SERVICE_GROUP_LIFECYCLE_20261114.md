# 服务群介绍、@与确认式生命周期

## 用户确认
- 健管专员为第一联系人；健康顾问介绍沿用整体健康管理、提供指导、协调专业服务的简洁版本。无诊断/处方行为的职责边界保留内部规则。小嘉保持独立AI身份。
- 正式服务状态生成待确认事项，当前所属健管专员（或超管）核对后执行；未确认不建群、不关闭。归档保留客户与有权团队查阅，关闭发送及AI回复。
- 年度连续续费沿用原群；其他服务结束后重新购买新建群。原服务仍有效时续接关联当前群，延期更新原正式记录，不新建群。

## 本轮实现
- 确定性实时待办投影：AnnualServicePeriod已激活生效；HealthPlan nutrition/medical_assist已active且已推送；Order明确medical_proxy流程或specialtyService/specialtyTerms键，已启动且付款/权益有效。无明确服务依据不猜测，不按商品名称或聊天文本创建。多个正式记录可关联一个仍有效的同类群。
- 专病订单期满/结案、方案完成/取消/到期、年度服务期结束生成归档确认。续接年度阻止旧群关闭；中断后新服务须先归档旧群。服务来源丢失或状态未知不自动关闭。
- 已有人工群可从匹配的有效服务待办确认关联；没有正式来源的旧群仍沿原人工配置路径，不伪造历史服务期。
- 确认时重新读取服务、人员、群版本；归档展示该来源下未完成随访/预约提示和待人工回复，并要求勾选核对及内部结束说明。人工需核对未录入系统的续约和诉求。
- 生命周期审计记录操作者、时间、来源。群级数据库操作锁串行化消息与归档；新群active唯一索引防重复。固定介绍由小嘉发送，不调用外部模型；持久pendingNotices重试箱与eventKey唯一索引保证欢迎/成员变更/结束通知不重复。
- @存储真实成员ID、姓名与角色快照；只能当前入群人员及本人客户，监管者不可作为群成员选择。医护有单独有人@我计数和定位；客户@通知进入原Inbox/nativePush链路。读消息仅清除返回消息对应本人的@状态，不清除人工待回复。
- 医护/客户已归档入口、历史100条分页。医护确认弹窗、成员选择与提醒，Taro Apple/Huawei与小程序共享功能，Expo备用网页源码也同步。
