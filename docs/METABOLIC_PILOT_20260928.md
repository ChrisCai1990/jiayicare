# 体重/代谢管理白名单试点

## 发布边界

从2026-09-28同步的origin/master（bd654284）独立开发；发布前再次同步。最终生产版本与构建、上传状态以交付记录为准。

这是12周健康数据记录与自动反馈的受控体验版，默认关闭、空名单，无公众开关。它不代表整个商业化付费路径或临床方案已验收。现有年度白名单、客户记录和服务权益不迁移。

## 三端入口

- Admin → 运营管理 → 体重管理试点（/metabolic-pilot）：超级管理员添加完整手机号或客户ID，填写经专业人员核对的适配依据。要求有效客户、所属健管专员和有效现有服务访问权。名单与年度试点独立。
- 启用白名单服务、允许新入组；前者控制自动反馈，后者只控制新的客户确认开始。开关按版本保存，旧页面不能覆盖新设置。
- 用户端 → 健康数据记录：名单内客户看到体验卡，本人确认后开始84天。提供事实比较、可选行动、记录偏好、暂停/退出、4/8/12周自动数据回顾与用户感受、结项后的维持需求求助。
- Staff → 体重管理试点（/metabolic-pilot）：所属健管/顾问/营养师及超管处理客户求助，填写可向客户展示的结果和实际用时；重复并发关闭只记一次耗时。
- 数据异常沿用日常健康数据监测原流程；本版不新增临床阈值或自动诊疗建议。主要体重反馈为数字比较，不凭单次变化判定减脂或代谢改善。

## 用户体验

使用“记录健康数据”，试点卡不要求完成每日任务，隐藏试点用户的必填完成计数和奖励式完成提示。提供愿意尝试/稍后/不适合的自主选择。

每次保存尽力返回即时反馈；附加反馈处理最多等待1.8秒，失败不改变记录成功状态。体重使用kg与之前不同日期的有效记录比较，不引用未来数据，数据不足明确说明。成功反馈保存规则版本、源记录ID及生成时间的审计快照；页面阶段回顾从当前有效数据重新计算，因此修改和删除会反映到报告中。

暂停不延长84天自然周期。结项自动按日期判断，不伪造专业结论。保留数据、用户阶段感受及人工处理留痕，不自动扣费或自动续订。

## 受控首版限制

- 提醒为用户打开记录页时显示的站内提示，未接微信订阅通知；不声称离线主动推送。
- 阶段回顾按访问时自动计算，未做定时推送或临床指标综合研判。
- 未新增自动饮食图片营养分析、个体化处方、付费产品及自动续费；需根据试点与专业审核另行配置。
- 首版控制台最多显示200位客户，单用户报告查询最近2000条服务期内记录；大规模开放前需要分页/聚合优化。
- 人工投入是处理时登记值，不能据此宣称已证明零人工或完整商业单位经济成立。
- 小程序需单独构建并上传开发/体验版；服务器部署不等于微信正式版发布。App/网页同步相同试点卡与接口。

## 明日验收

1. 在Admin为测试客户确认有效现有服务期和健管归属，邀请并打开两个试点开关。
2. 客户在新体验版记录页确认开始。另一非白名单账号应看不到卡片，直接调用开始接口也被拒绝。
3. 保存体重：即时反馈不靠人工回复；补录以前日期只比较更早记录；修改/删除后重新查看阶段数据。
4. 选择一个行动、切换记录提醒；暂停后仍可按原权限保存记录，但不继续试点反馈。
5. 提交一条非紧急求助，所属医护处理并登记实际耗时，客户刷新看到回复，非所属人员不能处理。
6. 测试撤回名单、关闭新入组和关闭全部试点，已有数据仍保留；不要给真实客户改日期模拟结项。
7. 4/8/12周与到期已用独立虚构测试库验证，真实周期效果、客户体验与续费仍需持续试点。
