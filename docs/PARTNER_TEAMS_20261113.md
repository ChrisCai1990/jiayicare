# 合伙人团队与负责人收益：多团队归属

员工和市场合伙人都可以独立成为负责人。管理员先在“合伙人团队与负责人收益”新增负责人团队，空团队也会列出；随后在每个团队下添加多名员工或市场成员。负责人收益仍按成员的推广、服务来源分别设置，已有关系和账目按原快照保留。

同一机构内，同一人员同一时间只能是独立负责人，或归属一个负责人团队。结束团队前必须先结束其所有成员关系；成员关系结束后可转入另一团队。服务来源只适用于员工成员。市场成员须先在市场合伙人档案中启用。

后端新增 `PartnerTeam` 团队登记，原 `PartnerTeamRelation` 保存成员关系和历史。发布前通过 `preparePartnerTeamIndexes.js --apply` 建立团队唯一索引，避免同一负责人重复建团队。旧成员关系不自动改写；部署前应确认是否存在尚未登记的关系。

隔离 MongoDB 的市场合伙人流程测试覆盖两个团队、空团队、多成员、重复成员、负责人身份互斥以及服务收益；索引迁移测试验证新增集合索引。管理端构建通过。

## 内部市场对接人与合伙人团队分离

内部员工可同时对接多位市场合伙人，一位市场合伙人同一时间只指定一位内部员工。此关系保存在独立的 `MarketPartnerLiaison` 集合，含生效、结束时间及结束原因；调整时先结束旧关系再指定新人。它不占用 `PartnerTeamRelation` 的成员位置，所以市场合伙人仍可独立带自己的团队。

对接关系仅用于内部责任分工，不改变订单的市场归因、合伙人团队成员关系或任何已配置的佣金，也不自动给内部对接人计提收入。若以后需要为内部对接人员配置业务奖励，须独立定义计提基数、比例/金额、结算节点和成本上限，不能复用合伙人团队负责人的规则。
