# 续约凭据与年度任务启用（2026-09-19，功能分支）

## 已确认规则及本轮实现

- 业务确认：续约依据为**已支付年度服务订单**；线下合同由客户所属健康规划师核验后补录。修改 User 的起止日期不等于确认续约。
- 新增独立 `AnnualServicePeriod`：关联客户、下一年度方案、来源订单/合同、服务起止日期、核验人员时间、凭据快照及启用状态。确认后不能直接覆盖，唯一索引限制一份方案一个服务期及一个订单只绑定一次。
- 已支付订单由后端检查归属、年度期限、付款/取消/退款状态。新商城服务包订单保存期限快照；旧订单仅明确的 `pkg_1y` 可直接识别，不根据商品名称或后来修改的配置猜测期限。其他旧订单需核实线下合同，不自动补造凭据。
- 当前仍需所属规划师（或超管）选择订单并核对服务期，尚未实现支付回调直接确认服务期。顾问、健管专员可查看，不能代替规划师核验合同。
- 员工端年度方案增加续约核验面板；规划师工作台“方案与评估”出现缺凭据及首次启用失败待办，链接定位方案年份与版本。凭据确认后不重复要求操作；首次派发异常保留待办，每日补同步。
- 续年派发同时要求：顾问审核发布、客户确认、有效凭据、服务期已开始且未结束、明确执行日期不超出服务期。提前确认不提前派任务。日期基准取客户确认与服务开始两者较晚值，不覆盖数据库客户确认时间。
- 接入既有启动/每24小时随访扫描，未新增分钟级扫描。凭据检查和年度任务同步本身不调用 AI；系统既有月度 AI 回顾是另一条链路，其费用/开关不因本功能消失。阶段评估自动扫描默认仍关闭。
- 任务拆分、常规随访、服务需求、方案用药/营养素承接、周期补给入口都加续年门槛；原首次/历史方案保持原链路。客户确认接口另补“已审核发布”检查。
- 重复同步保留规划师任务的进行中、已完成、已取消状态。续年补同步不会恢复人工停用的用药/营养素档案及暂停补给，已承接档案不被原年度方案覆盖。首次启用成功后不再每日调用用药/补给承接。

## 接口

`GET/POST /api/staff/annual-plans/:planId/service-period`，均验证客户岗位归属。POST 字段：

- 公共：`sourceType`、`startDate`、`endDate`。
- 已支付订单：`sourceType=paid_order`、`sourceOrderId`。
- 线下合同：`sourceType=offline_contract`、`contractReference`、`verified=true`。

日期严格为 YYYY-MM-DD；暂限制包含365/366天，起始年匹配旧方案 `year`，不与上一份已登记服务期重叠。明确排期越界需先由顾问调整草稿；不要绕过冻结或直接修改数据库。

## 上线前未完成项（不能视为全链路上线）

1. **未部署、未迁移历史资料、未修改真实客户或调度开关。** 本轮仅功能分支代码。
2. 客户端访问锁、用户 AI 权益有效期判断及血压/体重监测已接可信服务期（见下节），不改写原始档案。其他独立周期补给、阶段评估资格等仍需逐项统一，不得称所有调度均已迁移。
3. `year` 仍为旧自然年度键，不是合同年度ID。跨年、中断、同年多段合同、旧年度未完事项及总评/阶段评估时钟需继续校准。首次服务期未迁入新模型，不能核验其真实重叠；新字段不自动追认旧下一年度草稿。
4. 更正、撤销合同、换服务包、退款后的人工处置尚无完整流程。退款阻止新派发和受保护的客户写操作，血压/体重提醒在下一次每日扫描暂停；**不会自动撤销既有任务、停止其他独立补给/提醒或取消已启动服务**，不得据此宣称退款闭环完成。
5. 工作台续年方案查询上限100条、候选订单50条，需分页及覆盖完整性验证。凭据已保存但被日期校验等门槛拦截时，面板显示原因；尚未全面转化为各责任岗位异常待办。
6. 新凭据唯一索引须在真实 MongoDB 验证；既有 Task/FollowUp 的跨进程并发写入、部分失败重放仍需集成加固。当前测试证明重复调用状态保护，不证明所有并发组合完全无重复。成功后的后续日扫描失败仅日志记录，不把首次启用成功回退失败。
7. 无订单/合同自动识别补全、支付回调自动激活；已支付订单现需核对日期，不应称零人工续约。

## 后续：客户端访问与监测续期统一

- `resolveServiceAccess` 为客户访问锁、用户AI权益的有效期判断、血压/体重提醒提供相同口径。服务使用权不依赖方案确认，年度任务仍需原审核/客户确认门槛，避免循环等待。
- 服务期按北京时间整日生效，未来凭据不提前开启。没有新凭据的存量客户兼容原档案日期；空/非法旧日期仍沿用原宽松兼容，未做批量迁移。
- 新增凭据时冻结旧档案起止日期，仅用于新期开始前保留旧服务。进入第一段可信服务期之后，到期、退款或两段合同间空档均不再回退到可编辑档案日期。上一轮无旧期快照的凭据在首次新期开始前仍兼容原档案，未自动补造历史。
- 用户可在到期后查看本人已发布年度方案，并提前确认续年方案；首次方案仍需当前有效服务。未发布方案不得确认，未来续年确认不会提前派发。
- `/user/me` 附带不含内部凭据的 `serviceAccess`；有效期仅在响应中投影，不修改真实档案。App与小程序相应页面读取该状态，退款/到期不再仅根据旧日期展示有效。客户端自助保存不再接受 `servicePackage/serviceExpiry` 写入。
- 监测继续复用原 `service-cycle:*` 两条提醒和固定系统通知，不进首页任务区、不产生补做任务。按原启动/24小时扫描续期，已生效凭据的权限检查即时生效，提醒变化最晚下一扫描生效；无新增AI调用。用户主动关闭保持关闭。
- 服务无效或当天没有待提醒项时，仅将这一条监测通知设为已读，不删除历史、不影响其他消息。退款后的已生成通知可能在下一次扫描前仍存在。
- 凭据读取失败返回可重试503，不因数据库故障回退到旧日期放行。旧只读档案、商城白名单保留；当前没有全量迁移所有模块的服务权限规则。
