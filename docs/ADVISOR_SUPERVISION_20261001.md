# 健康顾问服务督办（2026-10-01）

顾问对所属客户进行服务督办；原岗位执行、健康规划师整体协调的权限不变。

- 只读汇总有效订单、已生效独立服务方案、保险服务、CareFlow 和原随访/服务执行任务。同订单、方案、年度具体事项和直接派单按明确来源合并；取消/完成源自动退出，订单完成后的独立临床随访继续存在。
- 当前属于顾问自己的环节不重复列入督办；异常优先，正常服务默认折叠，每页5项；加载失败明确展示。执行统计不增加督办数量。
- 顾问显式填写说明后可提醒实际处理人，或请求当前有效健康规划师协调。接收人工作台显示待反馈事项，填写实际反馈后退出，顾问可查看留痕；不自动发客户消息、不调用AI。
- ServiceSupervisionRequest 为内部往来记录，不创建 FollowUp；相同服务进度、发送人、接收人和类型用确定性主键防重。来源/当前负责人/所属顾问发生变化后重新校验；完成服务和已转交的旧提醒不继续显示，但记录不删除。
- 督办汇总及任务预览不调用历史任务修复、派单或服务推进函数。只读预览只显示原任务内容、实际结果和过程记录，没有改派、取消、完成入口。
- 通过当前有效 User 的机构及顾问归属限定无 tenantId 的原业务模型；接收人必须为同机构有效人员，协调接收人必须为 healthPlanner。不存在有效负责人时明确提示，不假报送达。
- 草稿方案、未支付订单、客户自助打卡 Task 不视为已启动的人员服务。服务建议和年度修订核对仍在已有顾问待办中办理，不复制到督办区。

验证：隔离Mongo/JWT HTTP集成及React交互测试覆盖归属/跨机构/停用/纯读/来源合并/自主任务排除/关闭/并发防重/反馈/版本冲突/折叠与分页。医护端构建。发布使用干净master及既有阿里云deploy.py --push --skip-data-migrations；不做历史迁移、不改变自动化开关。上线结果以部署日志与服务器版本核验为准。

修正：原任务归属优先，历史空 assignedTo 沿用 staffId。协调人仅取原服务明确记录或唯一同源督办任务，禁止按客户 assignedHealthPlanner 兜底；没有协调人不代表异常。
