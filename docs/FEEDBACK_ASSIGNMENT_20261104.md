# 用户反馈由管理员统一分派

用户确认：全部反馈先由管理员分派，不按问题类型自动指定金霞、蓝戈文或蔡冰奇。

## 使用入口

- 管理端 `/feedback`（业务管理 → 用户反馈）：机构超级管理员或 manager 先选择本机构有效员工，可填写内部处理要求。支持转交，或退回原负责人补充。
- 医护端 `/feedback`（运营协作 → 分派给我的反馈）：负责人查看反馈正文及内部要求、提交处理结果。当前负责人同时收到工作台“用户反馈待处理”待办，沿用工作台每 30 秒及窗口重新获得焦点时的刷新和待办提示；不是短信、微信或系统推送。
- 管理端“待核对”：管理员审阅负责人结果后填写客户回复并完成。负责人结果不自动公开。提交人继续通过原有反馈历史查看最终回复，App／小程序提交接口不变。

## 权限和状态

`unassigned → assigned → submitted → closed`；用户原有 `pending/resolved` 不变。历史未处理反馈视为待分派，历史已完成反馈保持原结果，不批量回填、分派或修改。

每次变更原子写入版本号和内部操作记录。重复、过期提交返回冲突；转交后旧负责人不再拥有该反馈的访问和提交权限。负责人仅得到本条反馈及处理要求，不增加客户档案访问权限；管理、人员选项、待办及处理接口均按机构过滤。

用户 `/feedback/mine` 显式选择公开字段，不返回负责人、内部意见和操作记录。正式账号注销队列及其办理期限不变，不通过本功能代替账号注销执行。

## 验证

`TEST_MONGOD=<本机 mongod 路径> node --test backend/test/feedbackWorkflow.integration.test.js`

测试仅创建本机随机端口、随机数据库的合成账号及反馈，验证真实 HTTP 鉴权、跨机构隔离、人员资格、重复提交、转交撤权、退回补充和公开字段隔离。管理端和医护端 Vite 构建验证；本机 UI 使用独立合成资料走通分派、负责人提交、管理员核对回复，不写入生产反馈。

2026-11-04 验证结果：本专项 12 项全部通过（含测试容器）；关联 `humanWorkbench.test.js` 8 项通过、1 项旧失败，失败位于第 123 行的缺少负责人异常断言，在未修改的 `133057c3` 基线上同样复现。本次未改变旧异常分派规则。

发布时使用干净 master 和 `scripts/deploy.py --skip-data-migrations`。内部安全评估资料、测试令牌、验收截图和生产操作记录不提交仓库。代码部署不等于人员已收到公司通知或已完成日常执行。
