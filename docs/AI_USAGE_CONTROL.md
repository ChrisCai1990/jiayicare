# AI 用量与预算管理

2026-09-12：已按用户要求先同步 GitHub 再部署，功能版本 `edc7eab6` 已完成生产接口与静态入口验收。首次发布异常保留在下方历史记录。

## 入口和权限

- Admin → 基础设置 → AI 用量管理，路由 `/settings/ai-usage`，本地默认端口 5175。
- API：`/api/admin/ai-control`。共享模型 Key 的总预算仅平台超管、未绑定机构的既有超级管理员可管理。机构超级管理员、普通医护、用户、HR 均不能读取或修改跨机构总用量。
- Staff 的会员报告列表显示“识别已暂停”和原因，暂停期间禁止普通“重新识别”。管理员恢复时保留检查点。
- 所有通过 `backend/src/utils/ai.js` 的通义千问 / DeepSeek 文本和视觉调用统一受控；WorkBuddy 外部 Agent、语音识别及语音合成当前不在这套 Token 台账内。

## 默认保护值

这些是可调整的初始保护额度，不是通过历史生产账单测算的正常成本。

| 层级 | Token 上限 | 调用次数上限 |
|---|---:|---:|
| 每日全部 AI | 2,000,000 | 2,000 |
| 每月全部 AI | 30,000,000 | — |
| OCR 每日 | 1,500,000 | — |
| 其他 AI 每日 | 500,000 | — |
| 同一报告累计 | 1,500,000 | 400 |
| 同一报告同一页累计 | 160,000 | 8 |

- 北京时间切换日/月；报告和页面累计额度不随重启、换任务编号、跨天或手动重新发起而清零。
- 同一供应商、同一模型连续 5 次异常后锁定；管理员检查后显式解除。已锁定通道不会被较晚返回的成功请求自动解锁。
- 空响应、截断和 OCR 无效 JSON 计入模型异常；下游医学证据校验不通过仍由原有审核保护处理。
- 页面预警比例默认为 80%，不会自动对外发送通知。
- 全报告执行 45 分钟、单页补提 15 分钟后禁止继续发起模型请求；已经发出的请求仍受自身硬超时控制。
- 金额上限默认不启用；单价默认留空。录入供应商实际人民币单价后可启用每日、每月费用上限。启用金额限制时，未定价的模型禁止调用。

## 预留、结算与异常

`AI 调用 → 读取开关/熔断 → 按所有适用层级原子预留 → 写入调用台账 → 供应商请求 → 记录实际用量并结算`

MongoDB 单个计数器使用带限额条件的原子增量，支持多个并发请求争抢同一额度。跨层级采用逐层保守预留；明确额度拒绝时撤销此前预留。数据库写入结果不明时保留预留并阻止请求，避免误放行。此实现不依赖 MongoDB 副本集事务。

- 输入预估使用文字 UTF-8 字节数加每图 16,384 Token，输出使用调用参数中的上限。实际视觉分词受供应商影响，因此这是保守预留估算，并非供应商账单的绝对封顶承诺。
- 返回有效 `usage` 时记录输入、输出与总 Token，费用按该请求发起时的单价快照计算。
- 超时、断连或未返回有效 `usage` 时标记“用量待核对”，保留全部预留。客户端断开不代表供应商没计费。进程中断前的 `reserved` 记录同样不自动退款。
- 如果实际用量超出预估，记录完整实际值，后续请求会按超支后的累计量被拦截。
- 未知用量暂不支持自动对账或人工退款；先到供应商账单核对，必要时追加报告/页额度。不能将“待核对”改成零消耗。
- 预算触限或记账故障以专用控制错误穿透 OCR 的重试、补漏、方向旋转与降级捕获，不会被当成普通识别失败继续烧量。并行页共享停止标记，并等待在途请求结束后才标记暂停。

## 暂停、续跑和结果边界

- 全报告触限：保留现有报告结果和 `parseJob` 检查点，只设置 `aiStatus=failed`、`parseJob.status=paused` 及原因。队列只恢复 `processing`，不会自动重启暂停任务。
- PDF 每个成功首轮页立即保存 `parseJob.firstPassPages`，批次汇总仍保留既有 `parseJob.progress`。图片报告保存已完成图片页。恢复时复用这些结果。
- 后续质量复核仍可能重新执行，但所有复核和原文校验继续扣除同一报告/页面额度。新发起的完整重新识别会创建新的结果流程，但不会清空费用计数。
- 管理员可追加某份报告或某页的 Token 与调用次数上限，追加不会绕过全局及业务限额；解除模型暂停和恢复报告是两个独立动作。
- 单页补提触限时沿用 `pageParseStatus.failed` 返回明确暂停原因，保留该报告已有审核结果。调整额度后，可在医护端重新补提该页。
- Staff 和用户 PDF 入口通过数据库条件更新防止重复入队；整份识别与单页补提互斥。既有队列仍按单后端进程串行调度整份报告；预算计数本身可跨进程原子执行。
- 用户端历史多图合并调用记录到报告总预算，不能伪造为逐页调用明细。
- 完成或暂停都不会自动审核或发布，原文证据约束保持不变。

## 数据与审计

- `ai_control`：单例策略及配置版本。保存采用版本比较，避免管理员互相覆盖。
- `ai_budget_counters`：日、月、业务、报告、页面计数及追加额度。
- `ai_usage`：每次调用的报告 ID、页码、业务、环节、模型、用量、费用、耗时和状态；查询索引在首次台账写入时建立。
- `ai_circuits`：模型失败计数和暂停状态。
- `ai_control_audit`：配置更改、解除熔断、追加额度与恢复动作；配置与恢复动作区分 pending / applied / conflict。
- 用量台账不保存报告正文、提示词、模型回复、客户姓名或密钥。报告页检查点属于既有医疗报告数据，仍通过原报告访问权限控制。
