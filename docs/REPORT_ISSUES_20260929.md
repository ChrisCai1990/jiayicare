# 报告问题及建议进入年度方案

本次需求：完整整理已解析资料中的异常及待核实问题，建议单独审核；确认后成为年度方案依据，不直接派发随访。

- 独立问题生成按分项分批读取所见、结论和数值，含胃镜、口腔。原标异常不会因模型判正常而消失；模型漏答、重复回答、超长项目、缺结果均保留待核实。原件未解析/缺页不能据此认定已覆盖。
- 原文、逐字原文建议、系统建议草稿、顾问确认意见分离，来源含页码。已有问题不能直接删除，只能注明不纳入原因；确认前逐项填写建议或待核实行动。
- 页面提供保存、覆盖核对、重新提取、人工核对。异步排队返回202并轮询，避免长报告请求超时。已保存旧稿保留在重提审计中，不运行历史数据迁移。
- 新普通报告生成annual_report_input；已有未确认旧稿可显式重新提取。已有服务关联仍保留旧工作流自动排除规则，可在页面显式整理为年度依据；不改变已有服务结案门槛或已发布历史随访。
- 顾问确认只保存annual_input状态并关闭该审核待办，不生成执行随访。年度生成按客户、当前报告版本、顾问确认状态读取问题，加入逐项evidenceCoverage及生成指纹。过期来源/排除项不作为行动依据；年度方案仍按原发布逻辑生成随访。
- 仅Staff/Backend改动，无App/小程序新增接口或客户展示变更，不扩大试点名单。

验证：25项专项测试通过（含实际HTTP路由、队列、胃镜/口腔漏提、长报告不丢项、来源防篡改、年度引用及实际React组件渲染），Staff生产构建通过。AI用模拟响应验证，未调用真实AI、未修改客户资料；未发布线上，真实报告输出待用户重跑。

复验入口：页面“病历与报告问题及建议” → “提取完整问题及建议” → 核对各项及覆盖 → 保存/确认 → 编制或补充年度方案。
