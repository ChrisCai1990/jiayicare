# 年度方案修订后的执行核对（2026-10-01）

## 本批结果

研判修订原先只改变方案内容，执行岗位没有新的衔接提醒。本批在已确认或冻结方案发生新增、更新、移除、跨分类迁移、日期/建议/模板执行内容变化时，与正式修订同一次写入保存 executionReview 标记。未确认草稿、仅来源/依据变化和旧历史修订不产生待办。

健康顾问工作台按方案合并一条「方案修订·执行安排待核对」，按当前会员归属展示，超管可处理；深链定位准确年度、方案类型及核对区域。四岗在原可见客户范围内查看差异与直接关联的医护事项、会员任务，健康顾问/超管才能保存核对结果。

顾问核对后选择无需调整或已在原流程衔接，必须填写实际说明。保存人员、时间、结论及核对时任务快照指纹；同一方案的当前待核对修订一起收口，未来新修订重新提醒。执行完成仍由原流程记录，本入口不自动创建、改派、重排、取消或完成任何任务，不调用AI、不发送消息。

## 并发和展示边界

- 修订与待办标记同文档原子保存；待办只读投影，不建平行任务。
- 保存核对前检查方案内容版本、当前关联任务快照；同文档完整修订数组作为CAS条件，旧页面、重复关闭、新修订并发不覆盖。
- 核对凭据写入不改变方案内容的 updatedAt，避免让正在编辑的原方案无故过期；完整数组CAS仍保护核对凭据。
- 任务快照是提交时读取的参考，不对独立任务集合加锁。保存后任务仍可在原流程正常推进，核对记录不是未来状态保证。
- 仅列 sourceAnnualPlanId 直接关联且属于同一会员的 FollowUp/Task。每类最多展示100条，未结束优先，超限明确提示原流程核对；不宣称覆盖所有间接订单/就医服务。
- 内部凭据存于默认不返回的 supplementRevisions，客户侧方案接口不新增内部字段。
- 原补充建议接口使用 $slice:-20 会裁掉早期正式修订和未处理核对，本批改为保留历史；不删除/迁移旧记录。
- 页面为空不占区域；角色只读、加载失败、版本冲突、未保存说明及跨方案迟到响应均有处理。既有岗位权限/自动化开关不变。

## 验证与发布

本地独立 MongoDB 7.0.34 随机库、真实 JWT 和 HTTP 验证：修订同次标记、四岗读写边界、跨机构拒绝、旧方案/任务快照拒绝、并发只关闭一次、原执行状态不变、后续修订再出现、原工作台归属过滤、超过20条草稿仍保留核对历史。只用合成数据，未调用真实AI。

规则测试及实际React交互验证：无效/旧修订不提醒、移除/迁移/日期待定、按方案合并、原日期展示、输入说明、只读权限、失败保留输入、跨方案迟到响应。原研判修订、日期提醒及上一批聊天异常交互同时回归。Staff生产构建通过后再发布。

按标准流程同步最新master并部署，使用 --skip-data-migrations；不回填历史、不改生产开关。发布版本与健康结果以外层 tmp/annual-execution-deploy.log 和验收回执为准。仅医护内部协作，无App/小程序交互变更。
