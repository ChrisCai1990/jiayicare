# 医护端巡检优化（2026-09-29）

## 行为变化

- 报告上传、科普推送、问卷推送和产品推送按姓名/手机号查询后端授权范围内的会员，支持分页；不再局限于预加载的200位。多选跨页保留，“选择本页”不清掉其他页已选项。搜索防抖、迟到响应隔离、失败重试；报告关联项目也隔离切换会员后的迟到响应。
- 首页和侧栏使用同一通知 Provider，统一读取通知汇总的用户未读消息、待处理转介和未读转介反馈；切页、重新聚焦、已读事件和30秒可见轮询刷新。加载失败保留上次数据，不伪装为零。
- AI待审增加会员/内容搜索、等待时长、优先级、排序；同级最久优先，每页20条，列表限制高度。取消报告随访草稿在两个分类重复计数。保留现有角色权限和处理入口，不新增自动审核、批量关闭、自动改派或历史迁移。
- 随访默认不限开始日期，保留工作台显式传入的日期；提供逾期未完成、今天、未来7天、全部日期，显示当前范围。重置清除日期限制。列表请求失败可重试，过时请求不能覆盖当前筛选。
- 跨方案服务概览仅在所有非取消任务完成时显示执行完成；有资料/有归档不再用完成勾代替。当前关注优先指向未完成执行任务。历史档案记录和可选问卷整理工具折叠，待人工确认的变化继续显示。
- 补齐身体成分/功能医学中文报告类型；最近随访展示转换内部服务/来源标识，原始数据不变；上传文案与已有7MB限制一致。
- 科普、问卷、产品推送失败均在弹窗内显示错误、保留选择，不再调用成功回调。

## 验证

新增14项规则及实际React/jsdom交互回归全部通过，覆盖第200位以外会员搜索、翻页、跨页多选、搜索竞态、通知共享与失败、三类推送失败、跨会员关联项目竞态、报告筛选竞态、日期跨年及完成语义。

医护端生产构建通过（1952模块；保留原有大包告警）。本地浏览器使用全部虚构数据检查报告弹窗、通知一致、待审组合筛选和随访日期入口；不调用生产写接口。

完整staff测试在新增前为70项/63通过/7失败；最终复验84项/77通过/相同7失败，新增14项全部通过。7项既有失败集中在体检工作区源码文案/结构断言、专家预约字段断言，以及档案刷新模拟器漏掉新增setter，未在本次放宽或删除。不能称全套测试全绿，也不能将测试替身失败直接算作线上故障。

## 发布边界

仅医护前端及测试文档变化，保留最新官网/后端提交；使用标准发布脚本并跳过数据迁移。实际发布版本和健康结果以部署日志及线上静态资源验证为准。

本批改善待审队列的检索与排序，没有自动处理历史积压。具体任务有效性、审核结论、认领或转交仍由有权限医护在原流程核对；未实现新的跨角色批量分派系统。
