# 健康规划师新订单企业微信提醒

客户订单在付款确认后进入健康规划师工作台时，提醒该订单当前所属的健康规划师。提醒不依赖客户回复，也不要求医护端网页保持打开。客户留言继续走原有企业微信消息提醒，两种提醒分别记账。

## 触发与收件人

- 仅处理客户发起、已支付（包括套餐权益抵扣形成的零元已确认订单）、未取消或退款、仍在办理的订单；未付款和员工发起的服务不触发。
- 订单须已有进行中的 `sourceType=order` 工作台任务，任务执行人须为在职健康规划师，且与客户当前所属规划师和机构一致。
- 只发送给该规划师本人绑定的企业微信账号。未绑定、身份或归属变化时跳过，不转发其他岗位；一笔订单最多一条企业微信通知。
- 通知只说明有新的客户服务订单，附医护端首页链接，不含客户姓名、订单名称、金额、备注或附件。登录医护端后在“用户下单服务进程”查看。
- 订单和任务保存后由后台扫描入队。发送前再次核验；企业微信接受后记为 `sent`，不等于员工已查看。发送结果不明确时不自动重发，避免重复打扰。

## 启用

默认关闭。先上线代码并建立 `WecomOrderAlert.orderId` 唯一索引、`Order` 扫描索引，再确认规划师账号绑定的是本人企微。当前错误绑定未处理前不得启用。生产启用时设置：

```
WECOM_ORDER_ALERTS_ENABLED=true
WECOM_ORDER_ALERTS_START_AT=<启用时的 ISO 8601 UTC 时间>
```

复用已配置的 `WECOM_CORP_ID`、`WECOM_APP_SECRET`、`WECOM_AGENT_ID` 和 `WECOM_SIDEBAR_ORIGIN`。起始时间确保历史订单不补发。新订单每 10 秒扫描一次；如果支付已确认但规划师任务稍后才建立，后续扫描会发现它。

## 验收

用合成客户和已绑定企微的测试规划师分别验证：待支付不提醒；支付并产生规划师任务后提醒一次；重复支付回调不重发；零元套餐订单覆盖；员工发起、退款、错误岗位、跨机构、未绑定账号不发送。查看 `WecomOrderAlert` 的 `sent`、`skipped`、`failed` 和长期 `sending` 状态。验证结束后再决定是否开启生产开关，不代真实客户下单或发送测试企微给真实员工。
