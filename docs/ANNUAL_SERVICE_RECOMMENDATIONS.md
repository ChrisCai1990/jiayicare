# 年度方案服务建议（首版）

服务建议是年度方案的独立附属记录，不是方案执行事项。年度方案推送后仍可追加建议，不覆盖已冻结的方案正文、既有任务或订单。

## 流转

1. 健康顾问保存年度方案后，可逐条填写发现的问题、客观依据、建议服务、建议时机和下一步说明，先保存为草稿。
2. 年度方案已审核推送后，健康顾问逐条确认发布。草稿不对客户展示；已发布建议不可覆盖，修订时另建新记录。
3. 客户在年度方案的独立“服务建议”区选择“需要协助”或“暂不安排”。建议不计入已完成/待完成任务数。
4. “需要协助”进入所属健康顾问的待办。顾问联系客户、按现有服务流程发起服务，并填写实际处理记录后关闭该意向待办。选择本身不自动创建服务订单或收费。
5. 方案删除时建议随删除日志快照留存，再清理关联记录。

本次仅支持人工起草；不自动从报告生成建议，也不把洁牙等处理视为既定医疗结论。后续可在已审核的报告/阶段评估中辅助起草，但仍需健康顾问核实依据并发布。

## 验证与发布边界

开发阶段后端全量测试：1373 通过、0 失败、2 跳过。专项测试确认建议不生成年度服务需求任务。医护端、两个 App 和小程序页面已通过 JSX 解析；本地 Vite 构建因沙箱无法读取跨工作树依赖而未完成，发布必须以服务器构建和健康检查结果为准。本功能不需要数据迁移，也不会自动生成客户建议或订单。小程序代码更新仍需单独构建、提交审核与发布。
