# 专家咨询复用原转介记录

2026-11-02 发布候选；生产状态以发布回执为准。

## 行为

- 健管完成咨询资料整理后，健康顾问在客户档案原“转介”入口发起外部医疗转介，并在专家咨询事项中关联该记录、选定本次专家；咨询事项只保存 `referralId` 和专家编号，不再重复写转介目的、问题和背景。单次咨询选 1 位专家，MDT 按规格选多位。
- 可选记录必须属于同一客户、由本事项健康顾问发起、未结束且未关联其他咨询。原转介所选专家须已开通本咨询类型、关联有效医护账号且报价在当前规格范围内。派发时再次确认该专家在名单中。
- 关联后，原转介从普通接收待办退出，原转介详情和发出记录提供咨询进度入口；专家在咨询事项中回复。订单、排班、多专家协调及随访审核仍由咨询事项处理。历史咨询事项原字段保留只读兼容。
- 医护端发起的事项在专家派发前可修改咨询问题；负责顾问在规划师派发前可更换原转介及专家。顾问明确提交后，规划师只能为顾问选定的专家选择空档并派发。更换转介会清空先前专家选择，需由顾问重新确认。健管收集资料阶段的两张卡片标明待办，不提供虚假的关联操作。
- 原 `Referral.status` 不由咨询流程改写；前端根据关联咨询的状态显示“处理中／已完成”。不把专家咨询回复伪装成原医疗机构反馈，也不自动生成专业评估或诊疗时间轴。

## 验证与边界

- 医护端生产构建通过；针对性后端路由与转介回归 16 项通过。服务端使用临时独立 MongoDB 完整执行专家咨询集成用例（包含关联、更换、派发、书面回复和结单），未使用生产客户数据。
- 本次不迁移历史咨询事项或原转介记录，不修改现有客户业务数据。关联操作发生时才会对所选原转介写入咨询关联编号，并取消其未完成的普通转介专业审核待办。

## 2026-11-03 流程修正

- 按业务确认调整为：健管提交资料 → 健康顾问发起并关联本人创建的原转介信、选择专家 → 顾问提交规划师 → 规划师排班派发。旧事项若已在规划师阶段但没有顾问选定专家，保留原排班入口以兼容历史。
- 负责顾问只能选择本人为同一客户发起、符合本次订单范围且尚可履约的外部医疗转介；没有扩大其他医护人员转介记录的读取范围。
- 独立临时 MongoDB 完整咨询流程回归和医护端浏览器模拟已覆盖转介关联、MDT 两专家选择、提交规划师及后续派发；不涉及生产客户数据。
