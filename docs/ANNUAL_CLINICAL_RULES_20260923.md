# 年度方案日期、统筹及展示修复

## 已核对原因

- 生成入口过去查询报告日期与少量项目字段，但主要通过旧 AI 汇总生成，并未把逐项已审核报告时间线交给模型。可能继续引用旧日期/缺失项目判断。
- 本次只读核对：1月有独立阴道超声；6月年度报告有子宫附件彩超。不能将两者的检查方式擅自等同，也不能继续忽略6月证据。原报告不修改。
- 既有同日统筹只有提示，没有输出校验。年度focus缺失补正也未带入本次已安排的近期项目，可能重复安排。
- 客户卡片不含timingReason，但旧端回退可能遍历原始moduleData；服务端需一并过滤，而非只改页面标签。

## 规则3

1. 输入包含已审项目日期、名称、方式及所见/结论，按时间排序。项目日期优先，缺失才回退报告检查日期；不使用上传时间，不以病理日期替代原检查日期。
2. 非空timingBaseDate必须有真实timingSourceId且日期一致；引用较旧同组检查需解释较新证据的处理。相关部位不等于检查方式相同。
3. 跨就医/完善检查/复查相差1—14天，优先同日；拆分需说明来源约束或不确定性。后端拒绝无说明的错开，不擅自修改临床日期。
4. 年度focus不得无依据复制近期项目。项目名称匹配的重复须独立复查理由及有效来源ID；胃肠镜历史纳入核对，但没有复查间隔依据不自动加每年胃肠镜。语义同义词去重仍需顾问审核，不能称绝对临床正确。
5. 内部时间推理/日期来源/拆分理由从客户原始moduleData递归过滤。医护端标记仅内部；随访人显示姓名，所属健管实际派单逻辑不改。
6. 指纹规则版本升至3，新规则不复用旧生成快照；同一规则/资料/模板重复生成仍复用。现有已保存/已确认方案不自动覆盖，不需删除报告或改资料触发。
