# 年度持续管理客户月度服务复盘设计

状态：首版已在本地实现，尚未部署；自动草稿仅为来源可核对的任务/服务记录数量汇总，未启用 AI 临床叙述。

## 上线范围

- 首轮仅对现有健康管理白名单中的金娟开放；后续按客户 ID 扩展，不按姓名判断，也不对所有注册用户开放。
- 仅对有效年度持续管理服务生成月份入口。不是年度客户、服务已结束的月份不生成待复盘。
- 设独立的 `MONTHLY_REVIEW_ROLLOUT_MODE=allowlist`、`MONTHLY_REVIEW_PATIENT_IDS=<金娟客户 ID>`，并叠加现有 `healthManagementRollout` 患者级开关；生产默认关闭。不得按姓名判断，也不得因为其他健康管理功能扩面而自动扩面月度复盘。

## 入口与定位

- 主入口：医护端客户详情 → 年度健康管理 → 月度复盘，按服务月份展示历史与当前月。
- 工作台只展示到期未确认的当月复盘，以及复盘中明确指派给本人的后续行动；不恢复“统筹全年”的笼统协同任务。
- 月度复盘是团队内部的服务管理记录，不等于阶段性健康评估，也不自动发布为客户的健康计划。阶段性评估仍负责临床和健康效果判断。

## 一个月一份记录

- 正常业务口径为每位客户每个服务年度一份年度方案。月度复盘以客户、服务月份作为唯一键，关联当期年度方案；续约后可按服务年度查历史，同一个月仍只允许一份。重复进入只打开同一份，修订保留时间、人员和版本记录。
- 月份状态：待开始 → 资料汇总 → 团队讨论 → 已确认。已确认后允许有权限人员追加更正，保留原确认版本，不静默覆盖。
- 系统可形成事实性草稿：该月服务任务及完成/逾期、最近的健康指标、阶段评估结论、客户反馈和遗留事项。每条自动摘要附来源和时间；缺资料写“待核实”，不由 AI 推断服务已完成或作临床结论。
- 团队逐项补充：①目标及健康变化；②本月服务执行与未完成原因；③客户体验、问题/投诉及处理；④跨岗位协作问题；⑤风险及待核实事项；⑥下月行动清单（事项、责任人、期限、状态）。
- 健康规划师负责召集、督办和确认服务复盘完成；各专业岗位只对自己负责的内容补充或核实。涉及诊疗、用药、风险调整的结论须交健康顾问/相应专业人员确认，复盘本身不得替代该专业审核。

## 客户可见与后续执行

- 完整复盘、团队讨论、投诉内部处理记录默认仅医护端可见。
- 只有经确认且明确需客户执行的行动，才通过既有任务/提醒机制同步客户端；不得把草稿或内部讨论直接推给客户。
- 下月行动引用既有具体服务任务，或由有权限人员确认后创建单项任务；同一行动不重复生成年度占位任务。

## 试点验收与扩面

- 先以金娟连续跑至少一个完整服务月，核对资料汇总、人工修订、责任人交接、历史回看及客户可见边界。
- 试点通过后增加客户 ID；全量开放需单独确认，不随代码部署自动开启。
