# 营养配餐方式（2026-10-21）

新生成AI营养草稿在方案模块上方可选：

- 中国居民平衡膳食餐盘：具体食谱、食物大类两种呈现。
- 早餐／晚餐各一包自研营养餐包，剩余预算分配常规食物。

每日总预算仍为营养师最终确认的 managementKcal，沿用餐次百分比。维持能量算法与理想体重参考算法均保留。餐盘依据为中国营养学会2022说明：https://dg.cnsoc.org/article/04/ya2PbmF0S_CNY0z_Vd9HGQ.html ，面积比例不直接视为能量比例；AI提供参考分量，实际食物热量仍需营养师核对。

一次AI调用生成三种草稿，默认食物大类。content.mealPlanVariants 保存各版本餐次，mealPlanSelection 指明当前版本，moduleData为当前可编辑内容；切换先保存当前编辑到内存，点击保存才写服务端。前端及后端原有items同步令用户端及小程序只读取选中餐次，不需单独客户端修改。未保存不能推送。历史方案不自动生成替代版本，可重新生成新草稿。

餐包由产品方给定每包50g、配餐计200kcal；图片标签1711kJ/100g，即855.5kJ/包（约204.5kcal），保留差异，不把预算口径称为标签值。shared/nutritionMealPlans.cjs保存每包完整营养成分。早晚每餐减200，午餐和加餐保持预算；任一早晚预算不足200时餐包选项不可用，等于200时不追加该餐常规食物。系统固定插入餐包行，AI只生成剩余常规食物，拒绝重复餐包。加餐0不显示食物。

已补充产品方2026-10-21提供的完整包装：蛋白奶昔·蛋白固体饮料，配料及鱼／乳／豆／谷物致敏源保存至PACK并传入AI，医护端可展开核对。包装冲调方法250–300ml温开水仅作产品资料，仍按早晚各1包，不自动采用标签每日2–3袋上限。餐包方案保存／推送前须营养师核实适用性；AI发现冲突可返回不可用原因，保留两种平衡膳食草稿。未调用真实客户数据做AI生成测试，未向任何客户推送。

验证：nutritionMealVariants、nutritionEnergyTargets、nutritionPlanAssessment共19项测试；覆盖区间、最终预算、每包成分、200边界、0加餐、完整性、切换编辑恢复、客户items、餐包适用性及固定餐包；医护端生产构建。部署结果以当次回执为准。

## 大类呈现单独修正

仅 balanced_categories 增加共享格式整理，去掉具体食材名称、合并同单位同重量口径的明确分量；明确前置总量优先，范围、替代选项及混合口径不猜测，提示营养师核对并保留原始记录。新生成、旧方案打开、切换及保存使用同一规则；保存前核对未确定分量。历史数据库不批量改写，保存后才同步客户方案。具体食谱及餐包算法不变，未恢复实时热量估算、AI重试或餐包主食限制。
