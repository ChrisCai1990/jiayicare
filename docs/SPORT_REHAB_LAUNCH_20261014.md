# 运动评估与复健服务

## 确认口径

- 首次运动能力评估：1000元，独立1次服务。
- 后续运动指导与复健训练：4次4800元、支付后90天；10次9800元、支付后180天。
- 线上及线下均可，时长、场地与具体方式由健管专员预约确认。
- 正式完成一场预约服务才核销1次；日常简短答疑单独留记录，不扣次数。
- 客户下单由健康规划师接单，再交健管专员预约，运动复健师执行、制定并直接发布方案，无健康顾问审核环节。

## 页面位置

1. 医护端客户 → 健康资料 → 基础档案与健康评估 → 运动筛查与能力评估：发送筛查表、查看答卷、首次评估与复评。
2. 客户 → 服务管理 → 运动管理：订单、有效期、预约、个性化运动方案。
3. 客户 → 服务档案 → 运动评估与复健：首次评估、每次训练、复评及日常线上答疑记录。
4. Admin → 商城商品：两个商品及三个收费规格；Admin问卷管理：12题预约前筛查；健康方案模板 → 运动复健：报告模板与两类训练方案模板。
5. 客户端：原有问卷入口填写，消息详情查看完整评估/训练报告，健康方案入口查看已发布方案。复用App和小程序既有通用能力，本次无需变更小程序包。

ServiceRecord为唯一运动记录，同一条记录在健康资料和服务档案展示。订单保存收费规格及有效期快照，不能随商品后来改价或改有效期发生变化。

## 实施与保护

- 自动筛查推送按订单幂等，医护端可以补发缺失推送；答卷保存题目快照。
- 筛查为收集信息，由运动复健师结合实际情况评估，不自动作医学诊断或批准运动。
- 服务记录先保存草稿，复健师确认后发布并推送完整文本报告；已发布记录不可覆盖/删除，可另建复评或追加更正。
- 方案模板只提供可填写结构，复健师针对客户明确目标、测试结果、训练、频次、注意事项及复评。
- 新订单不得经通用实际启动入口提前核销；需发布对应订单的正式记录，再确认实际完成。首次评估不能扣训练套餐，答疑不扣次。
- 核销使用订单版本与已用次数比较更新，单记录重复提交幂等；最后一次完成订单。服务包包含本项目时沿用既有权益预占/履约单机制。
- 客户资料遵循机构和负责团队边界；接单、预约、记录发布按岗位控制。

## 发布与验证

标准部署使用 `python scripts/deploy.py --push --skip-data-migrations`，跳过历史数据迁移。

上线目录配置脚本：`node backend/scripts/publishRehabCatalog.js`默认只读预演；核对后加`--apply`建立固定ID的2个商品、1张问卷、3个模板，重复执行不覆盖运营人员后续修改。

验证覆盖：商品及问卷模型校验、价格与收费规格一致、90/180天有效期、退款/到期阻止服务、首次/后续服务类型、重复/并发核销、岗位和机构权限、四类表单浏览器渲染、Admin和Staff生产构建。

本地浏览器测试使用合成数据。未用真实客户下单扣款或核销来测试；上线后首笔真实服务需按业务流程核对。
