# 最新调整：专病只记录健康情况

根据用户反馈，移除专病内的“服务与跟进记录”及人工关联入口。保留专病概况、健康变化时间轴、修订历史；服务过程统一从原随访计划和服务记录查看，避免重复归类。日常重要变化归档保持。既有记录及关联留痕保留，不迁移或删除业务数据。以下为上一版设计记录，服务聚合界面已被本调整替代。

# 专病界面修订

## 使用分工

| 界面 | 内容 | 日常操作 |
|---|---|---|
| 专病概况 | 首次至最新有据状态的概述 | 查看摘要更新人与时间、时间轴最新发生日期、未纳入变化提示；生成草稿后顾问核对保存 |
| 健康变化时间轴 | 就诊结果、日常重要症状和监测变化 | 复用已有报告审核；从日常反馈选择重要变化，核对专病及发生日期后归档，也可手工补充 |
| 服务与跟进记录 | 医护发起方案、实际执行任务和服务结果 | 查看原流程进度；确认未关联服务属于哪个专病；在原任务办理，不在此另造服务 |
| 修订历史 | 摘要旧版本和保存留痕 | 查阅历史，不重复录入 |

服务记录不以客户下单或单独支付为条件，会员权益内的服务同样汇总。方案、随访、服务结果按明确的方案/订单来源合并，仅用来源订单 ID 识别同一服务，不查询或判断付款状态。无来源关系的记录不猜测合并；已有记录不等于已完成。

## 实际修订

- 修复专病面板只收到专病类别记录的问题，新增按当前会员范围读取所有服务记录、就医协助方案和随访任务的只读汇总。草稿、进行中、已完成和取消保留原状态，每页5项。
- 专病关联优先使用稳定档案 ID 留痕；兼容历史明确的专病名称。未关联资料单列，顾问确认关联，可撤销本次人工关联。改关联不影响原方案、任务、结果或付款。
- 日常候选包含不适反馈及被标记异常的监测数据，显示最近50条、每页5条，更早资料明确提示原入口。顾问选择后带入原文，核对实际发生日期后保存；保留来源快照，同一来源在同一专病防重。原反馈流程不会被自动关闭，正常打卡不会全量灌入时间轴。
- 概况显示摘要更新时间/确认人、最新事件日期和待纳入变化数。生成草稿确认保存时记录时间轴覆盖版本；确认相同正文只更新覆盖留痕，不再新增重复历史。旧摘要未记录覆盖范围时明确提示，不能冒充全部已覆盖。
- 权限按现有可见会员范围校验；人工关联和日常归档由顾问/超管确认。更新按原档案数组比较，并发冲突返回409。未启用自动关联、自动临床结论、自动计费或历史迁移。

## 验证和边界

17项后端行为回归、3项组件交互回归通过，生产构建以执行结果为准。涵盖无订单服务、分阶段聚合、角色/会员归属、关联防重与冲突、日常来源防重、摘要覆盖、失败保护。

这次不代替顾问关联历史服务、归档真实日常反馈或生成真实客户AI摘要。没有明确关联来源的旧资料仍需人工确认，不保证所有历史服务已经正确归入专病。摘要覆盖提示针对已归档时间轴，不表示全部未关联报告或所有原始监测数据已审核。

当前仅本地修订；生产发布须以实际部署记录为准。
