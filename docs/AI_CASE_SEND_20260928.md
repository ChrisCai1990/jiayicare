# 专项研判发送与重复消息修复

## 原因及行为

原接口先保存员工消息，再同步等待AI；AI失败或网关等待超时会使前端保留原文并显示失败。再次发送会新建员工消息。回车路径也未拦截发送中的调用。

新接口在原子保存提问与运行状态后立即返回202，再启动AI。前端立即显示提问和“AI正在回复”，每2.5秒读取原主题列表显示最终结果。已保存和AI失败分开提示，失败时通过“重试AI回复”复用原提问。发送标识绑定内容、附件和发送人；并发占用以文档版本检查实现，不依赖单进程锁。

服务端失败状态持久保存；进程意外退出或状态写入失败导致运行状态停滞时，5分钟后允许原发送人显式重试原消息。新的运行token拦截旧任务的迟到结果，不自动重复调用AI。编辑、删除、结论操作在回复期间拒绝；模型版本保护拦截发送前读取的旧文档写回。

页面同步锁拦截连点/回车并发，输入法组合中的回车不发送。网络异常保留草稿及本次标识，重复点击核对同一发送。切换客户后迟到的请求结果不会写入当前客户主题。
