# 营养聊天草稿调度可靠性（2026-10-01）

## 范围与行为

日期提醒已在 d8234c02 上线；本批处理剩余聊天草稿调度。仅营养师频道参与，日常随访/健康顾问草稿继续停用；未知角色也拒绝。自动生成仍是待审核服务记录，不给客户发消息，不自动归档、不建立订单。

- ChatFollowupSchedule 使用内置唯一主键保存首次启用时间、半月截止点、分页游标和租约。每5分钟检查，首次只设置15天后的执行时间，不扫描上线前聊天；重启不重置。
- 每小时最多处理5个会话（至多5次生成器调用，底层AI预算仍生效）；多进程共用领取条件。管理员关闭开关和配置读取故障均停止调用，逐会话复核开关。
- 有新营养聊天且会员未删除才参与；缺少同机构在岗营养师时不调用AI，进入异常待办。生成调用带租户和负责人预算上下文。
- ChatFollowupJob 对会员唯一，手动和自动共用领取/状态屏障；已存在待审草稿直接复用，同周期不重新生成。单次最多500条/60000字符，超出不静默截断，转人工分段整理。
- 失败不自动付费重试。原工作台「风险与异常」显示原因，所属营养师/同机构超管可显式重试或填写实际处理说明。提交携带任务版本，防止旧页面关闭新任务。普通成功路径无新增确认步骤或独立页面。
- 重试保留失败窗口；迟到AI输出须通过当前令牌和有效期校验才允许落库。新草稿保存租户，日期和AI响应结构校验；提示词只依据聊天原文，使用实际窗口时间。

## 中断边界

生成过程超过10分钟视为异常，可由人员核对并显式重试/处理。数据库保存开始后的不明结果保持 committing，不自动重写、不强行解锁，避免晚到写入或丢弃后复活。若记录已存在，后续复用或原审核入口会补齐状态；若记录不存在，需运维核对该 recordId、原进程及写入结果后恢复。这是少量不确定写入的保守人工边界，不承诺外部AI请求严格一次。

失败关闭只记处理说明、人员和时间，不伪造完成的服务记录。旧生成结果、历史记录、其他自动化开关不迁移。回滚不得直接重启旧调度器（旧版本会重新纳入健管频道）；必要时先通过既有配置关闭 chatFollowupAutoDraft，再按标准流程回滚。
