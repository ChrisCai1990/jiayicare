# 营养评估需求单（2026-10-22）

## 使用方式

1. 机构超管在 Admin「服务流程管理 → 营养干预 → 配置评估与预约」核对文案、线上／线下方式并启用。新机构默认关闭。
2. 单次营养评估付款确认后沿用订单服务链路，自动进入所属健康规划师工作台「用户下单服务进程」。健康规划师从订单进入会员「服务方案 → 营养管理」，关联已付款、未使用的订单并转交健管专员。健康顾问不经手该订单。
3. 年度管理会员需要单次营养评估时，由所属健康顾问在「营养管理」直接发起，不要求另购单次订单。已在进行中的营养干预方案页仍可发起复评。发起时填写期望评估日期和具体时间、评估原因与重点关注问题，并使用会员当前分配的健管专员与营养师；期望时间供健管预约参考，不直接确认为预约。
4. 健管专员在工作台「服务事项」确认未来的预约日期、具体时间及方式。线上必须填写腾讯会议室信息，线下必须填写门店；预约确认后进入营养师工作台。
5. 营养师从工作台进入会员生活方式页面，完成膳食与生活方式访谈；已关联的单次订单自动核销一次，重复提交不重复核销。发起岗位在工作台或会员页查看需求、预约、结果和经办时间线。改约与取消留痕。

内部保留独立需求记录以承接预约和跨岗位流转；页面不再单独罗列一类服务。单次订单由规划师承接，年度临时需求由顾问发起，健管在工作台「服务事项」预约，营养师在「待我处理 → 随访」办理统一生活方式访谈。营养师主动发起和年度方案直派任务也使用同一访谈。需求单不另设评估表单。同一会员同类入口／同一营养方案只能有一张进行中的需求单。取消后订单仍可用于重新转交；完成后订单已核销，不能再次使用。

## 数据与接口

- `NutritionAssessmentConfig` 按机构保存启用、文案和预约方式，只有机构超管能修改。
- `NutritionAssessmentRequest` 保存发起来源、关联单次订单、责任岗位、当前状态、预约、评估结果、订单核销状态与只追加的事件历史；权限按机构和岗位校验。
- `GET /api/staff/nutrition-assessments/eligible-orders` 列出可关联订单；`POST /api/staff/nutrition-assessments` 发起；`POST /:id/booking` 预约／改约；`POST /:id/execution-task` 创建或读取统一访谈任务；`POST /self-lifestyle-interview` 由责任营养师主动发起；`POST /:id/cancel` 取消。`POST /:id/complete` 只用于已完成订单的核销重试。
- `GET /api/staff/nutrition-assessments` 供工作台和会员页查看；`GET /config` 读取配置。已完成仅指需求单完成，取消只在「全部」中显示。
- 「我关注的服务」的服务进度总览、订单预约、就医协助和既有体检方案均采用「待完成／已完成／全部」。服务完成以原服务或方案结案为准，已处理预约仍是单独历史。

## 验证与上线

专项 HTTP 测试覆盖顾问不可办理单次订单、规划师不可办理未付款订单、年度管理顾问无需单次订单、退款中不可预约、未预约不能提交评估、越权预约、缺少会议室、被禁用方式、改约历史及已完成订单的核销重试。统一访谈任务测试覆盖年度、顾问单次和营养师主动发起的任务识别、需求关联与结果回写。医护端与管理端需通过生产构建。尚未连接真实会员资料进行端到端验收；上线后需由机构超管启用配置并使用测试订单走完一次预约、访谈和订单核销。

## 2026-10-30 营养师生活方式访谈入口

健康顾问派发的单次营养评估，以及年度服务中的营养师营养评估任务，任务内容以膳食和生活方式调查为主。营养师从工作台打开任务时，进入会员「健康档案 → 生活方式」，使用已有膳食调查问卷的「生活方式访谈与核实」流程。已核实内容写入生活方式档案，未问清的项目保留待确认；支持暂存、版本核对、冲突确认，提交后完成原任务。

三种来源均建立或使用 `FollowUp` 访谈任务，并通过 `GET/POST /api/staff/followups/:id/lifestyle-interview` 办理。顾问发起的需求单只保存预约、流转、订单与结果，并在营养师打开时关联访谈任务。年度任务沿用原任务，营养师主动发起直接创建同类任务。原先仅填结论与建议的完成接口不再接受办理新任务，只保留已完成订单核销重试。
