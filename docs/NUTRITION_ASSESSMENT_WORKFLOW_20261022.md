# 营养评估需求单（2026-10-22）

## 使用方式

1. 机构超管在 Admin「服务流程管理 → 营养干预 → 配置评估与预约」核对文案、线上／线下方式并启用。新机构默认关闭。
2. 健康顾问在会员「服务方案 → 营养管理」选定已付款且尚未使用的单次营养评估订单，发起首次评估；已在进行中的营养干预方案页可发起复评。填写评估原因与重点关注问题。系统使用该会员当前分配的健管专员与营养师。
3. 健管专员在工作台「服务事项」确认未来的预约日期、具体时间及方式。线上必须填写腾讯会议室信息，线下必须填写门店；预约确认后进入营养师工作台。
4. 营养师填写评估结论和后续建议并完成；已关联的单次订单自动核销一次，重复提交不重复核销。健康顾问在「我关注的服务」或会员页查看需求、预约、结果和经办时间线。改约与取消留痕。

内部保留独立需求记录以承接预约和跨岗位流转；页面不再单独罗列一类服务。顾问从营养管理发起，健管和营养师在工作台原有「服务事项」中办理，顾问在原有服务进度区查看。不使用普通随访的方案模板，也不改动已有年度营养评估的直派任务。任一会员在同一入口／同一营养方案只能有一张进行中的需求单。取消后订单仍可用于重新发起；完成后订单已核销，不能再次使用。

## 数据与接口

- `NutritionAssessmentConfig` 按机构保存启用、文案和预约方式，只有机构超管能修改。
- `NutritionAssessmentRequest` 保存发起来源、关联单次订单、责任岗位、当前状态、预约、评估结果、订单核销状态与只追加的事件历史；权限按机构和岗位校验。
- `GET /api/staff/nutrition-assessments/eligible-orders` 列出可关联订单；`POST /api/staff/nutrition-assessments` 发起；`POST /:id/booking` 预约／改约；`POST /:id/complete` 完成并核销或幂等重试；`POST /:id/cancel` 取消。
- `GET /api/staff/nutrition-assessments` 供工作台和会员页查看；`GET /config` 读取配置。已完成仅指需求单完成，取消只在「全部」中显示。
- 「我关注的服务」的服务进度总览、订单预约、就医协助和既有体检方案均采用「待完成／已完成／全部」。服务完成以原服务或方案结案为准，已处理预约仍是单独历史。

## 验证与上线

专项 HTTP 测试覆盖未购买不能发起、退款中不可预约、未预约不能提交评估、越权预约、缺少会议室、被禁用方式、改约历史、营养师完成后订单单次核销与重复提交防重。医护端与管理端均需通过生产构建。尚未连接真实会员资料进行端到端验收；上线后需由机构超管启用配置并使用测试订单走完一次预约、评估和订单核销。
