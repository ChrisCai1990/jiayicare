# 专项研判用药上下文修复

## 已确认原因

用户指定年度研判原先未选择 medications。页面勾选后，09:59 的持久快照确有三条用药、13项来源，但共262052字符；provider对整份JSON取前45000字符，排在206738字符报告之后的药名全部未发送。sources位于开头，导致显示已引用而正文缺失。recentMedication空白不能证明独立Medication集合没有记录。

## 修复

- 独立用药/营养素保留全部临床字段和所有记录，不发送附件地址、打卡和配药工作流元数据。关键资料本身过大则明确失败，不静默丢药。
- 报告项目保留名称、结果、单位、参考范围、状态、所见/诊断、日期等临床字段，排除内部归类标识、空默认值等冗余。原数据库资料不变。
- 每类资料独立分配篇幅，旧AI分析最多6000字符。只压缩具体字段，标记省略，不截断JSON；最终请求保持45000字符以内。
- system prompt明确独立用药表优先于档案空字段和旧回复，不得凭缺失资料猜测映射故障或声称创建了人工任务。
- 专项讨论持久保存实际发送的压缩快照，来源清单提示有压缩；历史消息不回写。
