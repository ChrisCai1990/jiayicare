# 病历与报告随访草稿

功能分支实现，尚未部署。与专业健康评估分开存储，不写入专病，不重建年度方案。

## 数据流

1. 门诊病历、住院病历、检验、检查、体检报告审核通过并 `save` 时，同次持久化来源事件。已审核临床内容修订生成新序号；无关保存不触发。未审核、处方、问卷等不接入。
2. 事件唤醒后台 worker；后端启动和每 24 小时恢复队列。唯一来源键防止重复建立草稿，来源成功落库后才标记事件处理完成。没有历史批量回填，也没有每分钟全库扫描。
3. 保守排除已有订单/服务计划、资料服务记录、异常复查、条件式就医服务、原随访或转介关联的来源，继续由原闭环承接。
4. AI 只读取已审核结构化原文，不输入文件/base64、AI分析总结或联系方式；只提炼原文明确的当次建议，不根据异常数值自行增加医学复查项目。沿用现有预算控制、原子抢占、版本校验及超时处理。
5. 有建议进入顾问工作台审核；无建议标记“无新增行动”，不增加工作台任务，顾问仍可在页面人工补充。失败可重试或人工接管，失败不自动循环扣费。
6. 健康顾问终审冻结快照后，复用既有发布器逐条幂等派发健管专员随访；需要服务时配对规划师需求，可关联已有服务并回写结果。发布失败保留审核任务及原快照，只补未发布任务。

## 页面与权限

- 工作台“审核报告随访”进入客户年度管理页中的独立“病历与报告随访”区块，仅复用页面容器，不参与年度方案生成。
- 显示审核来源快照、状态及跳过原因；草稿支持标题、日期、内容、类型、服务需求编辑和删除。待处理/生成中不可直接批准。
- 审核仅健康顾问/超管且校验客户可见范围。内部审核、规划师服务需求不出现在客户随访列表，也不能由客户接口完成或提交表单；同样补齐专业评估内部任务保护。
- 新正式任务 `sourceType=report_followup`，不同于 `professional_assessment`；均可进入服务关联机制。

## 版本和边界

- 生成前后及终审前重新核对来源患者、审核状态、事件序号与内容指纹。报告修订/撤审后旧草稿不能继续发布；已批准任务不自动撤销或覆盖。
- 同报告已有批准随访时，新版需顾问对照历史计划决定增量，不自动再派一套。跨不同报告同义建议仍未实现语义合并。
- 报告来源事件覆盖 Mongoose `save` 审核/临床编辑；原生数据库修改及 query update 不是通用入口，不自动补跑。并发跨集合审核仍需真实数据库验收。
- 顾问缺失时任务交规划师/健管专员/原审核人补齐归属。来源失效后的旧待审记录可退回；既有已批准历史不改动。
- 首次生产部署需确认来源事件索引、`ReportFollowUpDraft.sourceKey` 唯一索引和既有 `FollowUp.assessmentActionKey` 唯一索引存在。
- 本地模型替身及HTTP测试不代替真实MongoDB重启/并发、多岗位浏览器端到端验收；本轮未调用真实患者资料的AI生成。

回归入口：`backend/test/reportFollowUpSource.test.js`、`reportFollowUpWorkflow.test.js`、`reportFollowUpsRoute.test.js`；需连同原会诊、服务关联、体检流程回归。
