# 嘉医汇系统内服务群与团队监管

## 范围

- 客户在嘉医汇 App 的“消息 → 我的服务群”发起群聊；不使用微信或企业微信会话。
- 每名客户对应一个系统服务群。当前分配给该客户的医护人员自动构成服务团队；人员交接后按最新分配重新核验读写权限。
- 医护端“系统服务群”可查找本人负责的客户建群、查看、回复；团队负责人依据现有 `Team.mentorId` 与成员 `Admin.teamId` 只读监管团队当前负责客户的群。
- 群列表展示“待团队回复”，定义为最新客户消息晚于最新医护消息。监管查看留独立访问记录。
- 第一版仅支持文字，打开页面时每十秒刷新。医护回复会给客户发送一条不含原文的站内消息提醒。没有 AI 自动回复。

## 权限与数据

- 后端从当前 `User` 的各岗位分配字段推导群成员，不信任浏览器传入的团队、客户或员工标识。
- 客户只可读写本人同机构有效群；医护需当前被分配给客户；团队导师只能读，不能代发。
- 自定义角色需具有客户和服务助手查看权限，发送还需服务助手 `send` 或 `create` 权限；查询失败时拒绝。
- 群、消息、监管访问记录均带机构与客户标识，并纳入账号注销个人资料清理规则。
- 每次最多回读最近一百条消息；监管页不提供导出。群消息与现有一对一 `Message`、企微存档 `ServiceGroupMessage` 分库存储。
- 医护端服务群列表每页一百个，支持继续加载；筛选与计数作用于已加载的列表。
