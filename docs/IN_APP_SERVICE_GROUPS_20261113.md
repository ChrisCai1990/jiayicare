# 嘉医汇系统内服务群与团队监管

## 范围

- 客户在嘉医汇安装版 App 或微信小程序的“消息 → 我的服务群”发起群聊；群消息存于嘉医汇系统，不进入微信原生群或企业微信会话。
- 每名客户对应一个系统服务群。客户当前分配的健管专员在医护端按客户从当前已分配人员中勾选入群名单，保存时创建或更新群；客户不能自行建群。超管保留管理权限。
- 只有被勾选且仍是该客户当前服务人员的人可读写；人员交接后旧成员即使还留在名单里也失去权限。健康顾问、营养师、就医专员担任团队负责人时，可只读监管本团队已入群成员服务客户的对话记录；本人负责客户即使未入群也可只读查看。健管专员未入群时可只读查看本人负责客户的对话。
- 群列表展示“待团队回复”，定义为最新客户消息晚于最新医护消息。监管查看留独立访问记录。
- 第一版仅支持文字，打开页面时每十秒刷新。医护回复会给客户发送一条不含原文的站内消息提醒。没有 AI 自动回复。

## 权限与数据

- 后端将健管专员提交的名单与当前 `User` 岗位分配、人员在职状态交叉核验；监管按有效团队负责人及在职团队成员关系判定；名单版本防止旧页面覆盖新设置。
- 客户只可读写本人同机构且已配置成员的有效群；医护需既入群又当前被分配给客户；团队导师只能读，不能代发。
- 自定义角色需具有“我的会员”查看权限；服务群页面与家庭服务助手权限独立。建群、查看和发送仍分别校验客户健管专员、本团队监管关系，以及当前分配与入群名单；查询失败时拒绝。
- 群、消息、监管访问记录均带机构与客户标识，并纳入账号注销个人资料清理规则。
- 每次最多回读最近一百条消息；监管页不提供导出。群消息与现有一对一 `Message`、企微存档 `ServiceGroupMessage` 分库存储。
- 医护端服务群列表每页一百个，支持继续加载；筛选与计数作用于已加载的列表。
