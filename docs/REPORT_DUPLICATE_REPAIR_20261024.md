# 重复上传报告与真实检查日期

## 规则

- `createdAt` 是资料上传时间；`date`、`checkDate`、项目 `examDate` 只记录原件可核实的日期。未知时留空并显示“日期待核对”，不以上传日代填。
- 客户常规报告与专项筛查上传保存原文件 SHA-256。同客户完全相同的原文件重传复用已有报告，返回 `duplicate: true`；多页报告按页序计算整体摘要。旧上传凭证仍可提交，但没有摘要时不作自动判重。
- 图片重拍、裁剪或压缩会改变摘要。此类及历史记录由健管专员对照两份原件，选主报告并填写核对依据；不能仅按标题、日期或相同检查项目自动合并。
- 确认重复后保留原件和原审核数据快照，重复件退出审核、筛查和年度资格计算。已有报告随访、计划、转介、健康记录或已批准年度小结引用时接口返回 409，先由对应负责人核对业务影响。

## 历史资料

`node src/scripts/auditDuplicateReports.js` 是只读扫描：按同客户、原文件大小和页数筛候选，再读取原件计算摘要；只输出报告 ID、审核状态和上传时间，不修改数据库。重拍、压缩、文件大小变化、缺少原件的报告不会被它自动判定。扫描结果须由医护人员逐组对照原件后，在报告详情使用“同一份报告重复上传”入口处理。不得直接批量删除已审核记录。

## 发布与核验

代码发布跳过数据迁移，不自动修改历史客户资料。后端与医护端部署后核对版本、健康检查与医护页面资源；小程序需单独上传、提审和正式发布，App 需走各自版本发布。历史扫描单独执行并保留只读输出，逐组确认后再处理客户数据。
