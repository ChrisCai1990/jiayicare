# 报告提取与审核规则（2026-09-20）

目标：完整、准确、可追溯地提取报告；系统只匹配 Admin 已维护的标准项目；一线仅核对原文与数据。

## 六条业务规则

1. 忠实原文，保留名称、结果、单位、参考范围及页码/栏目/方式/部位/标本上下文；不能猜测或把文档内容当指令。
2. 只匹配 Admin 有效末级节点；关键字段冲突或歧义时待维护，不创建分类或兜底全科。
3. Admin 确认的匹配关系可按明确上下文复用、查看、撤销；系统建议不是已经确认的规则。
4. 补提只补缺失、保护人工修改和删除；疑似跨页重复提供定位对照，不自动删除有差异的内容。
5. 内容审核与分类维护分开。草稿可保存；体检/检验/检查报告完成审核须有有效检查日期、已确认机构或明确“来源机构不明”，以及已处理的识别疑点。
6. 已完成结果不重复处理；局部失败不扩大，记录审核日期及有效审核时长。

## 本次实现

- 用五条提取原则和原有兼容 JSON 字段替换主提示词的长错例清单；机构特定模板及既有影像原文核验保留。新增 specimen、modality、reviewIssues。模型输出不能自带已归类/已人工审核标记。
- 分类仍使用 Admin 分类树、别名和绑定目录；增加方式/部位冲突排除，移除同页尿常规推断。明确尿/便/血常规上下文无法匹配时，不退回跨体系同名单项。
- Admin 分类管理新增报告维护队列、原名查询（含已归类项目）、指定已有分类确认，以及已确认规则撤销。确认按原名、栏目、医嘱、标本、方式、部位、单位复用，不需要新增标准项目。并发冲突不会任意选择类别。
- 员工审核的分类改为只读。后端也拒绝项目接口修改分类字段，整表保存按服务端分类及当前证据重新匹配，不信任客户端提交的分类键。
- 疑点和疑似重复支持跳到来源页/条目对照。重复提示当前采用名称与检查上下文比对，属于保守提示，非语义重复全覆盖，也不自动删原件。
- 补提兼容缺少可选栏目的同名项目，保留不同日期/标本；记录人工删除身份，防止补提恢复；补提和 PDF 最终结果写入增加版本校验。
- 主提示词缩短降低预占成本，但不修改管理员预算值。页额度不足不再污染整报告停止状态；其他页可继续。输出截断/格式错误不计服务熔断，OCR 调用故障熔断按报告隔离。已有旧熔断和暂停记录不自动改写。
- 重试保留已有检查点；完成报告拒绝重复整份解析，使用明确的单页补提。运行中断和预算暂停仍按既有管理员恢复流程继续。
- 两个审核入口共用日期/机构/疑点校验；草稿不受完成门槛限制。机构归一化不覆盖已有项目级来源。
- 审核界面每 15 秒发送活动记录，隐藏页面或 120 秒无操作停止。服务端仅累计不超过 20 秒的已观测间隔，忽略重复序号、断线长间隔和同人员多窗口重叠；按会话保留人员记录。列表显示审核完成日期和累计时长，审核窗可查看分人员累计。历史无记录显示“时长未记录”，不反推。
