# WorkBuddy AI辅助研判测试接入

## 边界

- 客户专题、医护讨论、资料快照、阶段结论和审核记录保存在嘉医系统 MongoDB。
- WorkBuddy、通义千问和 DeepSeek 只作为可替换的分析供应商，不持有业务主键关系。
- 只有健康顾问确认后的专题结论，才会进入年度管理方案的生成上下文。
- 测试阶段只能使用脱敏测试客户，不向任何外部供应商发送生产客户资料。

## WorkBuddy 配置

WorkBuddy 官方企业版支持在“企业智能体 → 开发集成 → API 集成”中使用企业 API Key 调用 Agent。先在企业后台创建专用的“嘉医客户健康研判”Agent，并完成 Test Run，再把控制台生成的以下参数放入测试后端运行环境：

```text
WORKBUDDY_API_URL=
WORKBUDDY_API_KEY=
WORKBUDDY_AGENT_ID=
PUBLIC_API_ORIGIN=
```

不要把真实凭据写进 `.env.example`、Git、交接文件或聊天记录。

`backend/src/utils/workbuddy.js` 是唯一厂商协议适配点。首次拿到企业控制台生成的 API 示例后，应在这里核对请求字段、流式响应、文件上传/产物下载格式；业务路由和前端不应直接依赖 WorkBuddy 字段。

## 测试入口

医护端进入客户详情，选择“AI辅助研判”：

1. 新建一个独立健康问题主题。
2. 选择允许本轮读取的客户资料范围。
3. 选择 WorkBuddy 或“自动选择”。
4. 输入问题，可附带最多 6 张图片。
5. 检查每轮回答的供应商、耗时、资料快照来源。
6. 让 AI 整理阶段结论，由健康顾问编辑并确认。
7. 生成年度管理方案，确认只引用“已确认”结论。

## 供应商评估

同一组脱敏案例分别使用 WorkBuddy、通义千问和 DeepSeek，至少记录：

- 事实与原始报告一致率；
- 图表、截图和多图关联理解；
- 是否明确指出资料缺失；
- 是否出现编造诊断、数值或用药；
- 医护人员修改量；
- 响应耗时、失败率和单次成本。

在完成真实盲测前，“自动选择”只表示按可用性路由，不宣称某供应商一定最优。
