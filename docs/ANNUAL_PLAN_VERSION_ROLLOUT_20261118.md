# 金娟年度管理流程扩展至其他成员（2026-11-19）

## 用户确认的边界

金娟已有旧版年度方案，仍可在新版年度管理页面查看和办理。因此全员开放沿用金娟的页面及年度能力，不批量改写历史方案、目标或随访。此前提出的逐方案版本迁移方案已废弃。

## 实现

- 新增独立配置 `ANNUAL_FLOW_MODE=all`。未设置时仍仅向原金娟名单开放；设置后所有成员使用相同的年度管理能力。`MANAGEMENT_REVIEW_MODE=phase_assessment` 与原名单保持不变，避免把独立阶段复盘一并放开。
- `GET /patients/:id/management-reviews` 返回独立的 `annualFlowEnabled`。年度方案页、当前筛查、专项关注按钮读取该字段；阶段复盘继续读取原 `restored`，互不影响。
- 对原有已推送、尚未客户确认或未保存审核状态的方案，允许已审核的专项筛查补入和逐项修订；驳回方案仍拒绝。缺结构化目标的历史已确认方案继续显示执行步骤，不因全员开关倒退成待建方案。
- 已有普通随访不因全员开关改变到期日或开放“未完成后预约”。新生成年度随访在 `formData.annualFlowVersion` 写入 `2`；这项任务标记只用于新的随访操作，不迁移旧任务。原金娟试点任务继续兼容。后续任务继承标记。

## 验证与发布

- 需在 `ANNUAL_FLOW_MODE=all` 下验证页面构建、旧方案修订、旧任务日期不变、新任务可继续推进、金娟原行为、阶段复盘名单未扩大。
- 先发布代码，再设置生产配置并重启后端；启用后只读抽查金娟和其他成员的年度页、已推送未确认方案与原随访。不能把代码提交或部署等同于功能已启用。
- 若启用后发现旧任务或页面异常，撤销 `ANNUAL_FLOW_MODE` 并重启；方案与任务数据不进行批量回滚，因为本次不做批量迁移。
