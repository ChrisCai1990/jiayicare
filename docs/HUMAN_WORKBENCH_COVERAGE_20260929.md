# 人工工作台漏接修复

本轮修复核查中确认的漏接路径。所有新增提醒都读取原业务记录，不代替人工审核，不重建、清理或自动完成历史任务。

## 已实现

- `/staff/ai-todos` 移除各来源的 50/100/200 条静默截断；随访审核在数据库查询阶段即限制本人客户和审核岗位。保留原待办前端分页、检索和类型筛选。
- 服务执行工作台先按活动状态查询，再应用原流程判断；不再被已完成历史或 100 条展示上限挡住。加载失败明确提示，不显示成“无任务”。
- 微信客服接管按明确的 `assignedTo` 保留可见性，普通审核仍按客户归属；不扩大普通客户查看权限。
- 普通报告解析失败进入“报告解析失败·待人工处理”；已审核和正在解析记录不混入，人工专用报告仍走原审核入口。
- AI 健康整理逐年度、逐生成记录、逐专业维度投影；保留已审、空内容、自助生成排除规则。深链包含年度、专业、生成时间和索引；新增记录后按生成时间重新定位，记录失效显示提示，不静默跳到另一条。旧顶层结构兼容审核。
- 官网咨询覆盖新线索、已联系未办结、承接中断恢复、已承接未关闭；保留实际下次跟进期限和新咨询既有两工作小时时效。不凭空设定已联系线索的跟进期限。已关闭承接不复活来源线索，进入原业务页时定位原事项。
- 规划师查看本人客户、超管查看本机构的责任异常；报告、档案、健康整理、用药、营养素、方案、随访、阶段评估、营养随访草稿及转人工有待处理事项时，检查对应负责人缺失/停用/岗位不匹配。提醒去原客户资料核对归属及任务指派；不自动改派。
- 超管的服务方案草稿审核不再错误限制为“草稿规划师等于超管本人”。

## 验证

专项回归、组件渲染和真实本机隔离 Mongo/HTTP 验证共 54 项通过（35 + 3 + 16），包括：

- 前面存在 60 条他人待审时，本人 65 条仍完整返回；服务任务 105 条不会截到 100。
- 报告失败保留，审核后清除；客服转派可见、其他人员不可见、完成后清除。
- 旧年度待审不被新年度已审结果掩盖；前插新记录后原深链仍定位原记录。
- 机构、角色、客户范围和原承接记录权限；关闭承接后提醒消失。
- 咨询面板完整计数、分页、原记录跳转、请求失败和队列缩短时的显示。

测试仅使用 `127.0.0.1:27961` 的随机 `human_workbench_test_*` / `service_intake_test_*` 数据库，无真实 AI、收费、客户通知或生产数据修改。

医护端 Vite 构建通过。最终整合主线后的验证及发布状态以本任务最终结果为准。

## 边界

这是已确认漏项及主要责任异常的修复，不是对全部业务状态的全局零遗漏证明。风险评估的历史年度、未启用的自动任务、业务尚未形成持久记录的临时 AI 预览等，不能据本轮测试称全部覆盖。生产存量待办尚未逐条清点；没有执行历史迁移。

当前待办接口返回当前权限范围内完整列表，客户端分页；数据量继续增长时，应改为同一筛选口径下的服务器分页和真实总数，不能重新引入静默上限。
