# 群消息持续采集与随访草稿

2026-09-14：用户授权接入已有授权群，自动生成草稿，人工确认后进入正式随访。

## 数据流与边界

官方 Finance SDK → 解密 → 本机构已绑定且 archiveConsent=true 的群 → 官方 check_room_agree 同意状态 → 签名桥接收件 → 本地规则生成 ServiceGroupEntry 草稿 → 员工核对 → FollowUp。

- SDK 每批最多20条，单个进程每15秒继续拉取，以 MongoDB WecomArchiveCursor 保存序号；数据库租约避免并发拉取，失败不跨过未完成消息。接收端按群和消息ID去重；草稿按发送人、中国日期和规范化原文去重。未授权群、非发送事件、未同意的消息跳过；以后授权不自动补入此前跳过的数据。
- 仅同步已有群授权；不替客户或员工同意。要求群内外部联系人均同意，且消息发生于同意之后；状态缺失或接口失败不放行。
- 文字、9MB以内的PDF/JPG/PNG/WEBP可接入。附件在私有OSS短时暂存，沿用人工确认成员、类别的归档流程；不自动OCR、不自动审核。其他类型不下载，支持类型的超限文件只保留查看企微原件的提示。
- 跟进筛选在服务器本地按明确的随访、复查、报告解读、联系等表达进行，不调用外部AI，不保证覆盖所有自然语言表达。一般闲聊不建任务；症状或用药只产生医护核对草稿，不提供诊疗建议，也不替代急症处置。
- 不根据发送人或群名猜测患者；草稿患者始终留空。只提取明确完整年月日，模糊日期保留原文，须人工确定。
- 引用原消息的变更可更新尚未人工编辑的草稿；无明确引用时生成变更核对草稿，不猜测对应事项，不修改正式随访。不会自动回复客户。
- 自动草稿确认前必须选择本群成员、有效日期、本群服务团队负责人；后端同时检查跟进创建与编辑权限。确认后使用草稿稳定ID创建 FollowUp，重试不重复建任务。

## 运行配置（值只放服务器安全配置）

- WECOM_CORP_ID、WECOM_ARCHIVE_SECRET：企业身份和存档专用凭据。
- WECOM_ARCHIVE_KEY_DIR：存档SDK、公私钥目录。默认 `/var/lib/jiayicare/wecom-archive`；版本1用 private.pem，后续版本用 private-vN.pem，不能覆盖旧版本。
- SDK：sdk/libWeWorkFinanceSdk_C.so，来自官方文档链接的 Linux x86 v3 20250205 包；Python3 ctypes 通过私有管道与Node协作，不记录明文。
- SERVICE_GROUP_ARCHIVE_ENABLED=true、WECOM_ARCHIVE_COLLECTOR_ENABLED=true：启用接收及持续采集。
- SERVICE_GROUP_FOLLOWUP_DRAFT_ENABLED=true：启用本地规则草稿生成，与外部AI总结开关无关。
- SERVICE_GROUP_BRIDGE_SECRET、SERVICE_GROUP_MESSAGE_KEY：签名和入库加密，复用已配置项。
- SERVICE_GROUP_BRIDGE_TENANT_ID：明确机构；缺省只匹配 tenantId:null 的既有群。

工作目录为 backend，运行 `node scripts/wecom-archive-worker.js`；`--once` 可跑一批用于验收。生产由PM2管理，进程名 `jiayicare-wecom-archive`。关闭上述采集开关并停止该进程即可停采，不删除已收件消息。采集状态以最后成功时间、错误码和游标为准；配置存在不代表持续采集在线。

## 日常检测与沟通接入既有记录（2026-09-14）

- 日常检测图片沿用群资料待归档及 ServiceGroupReceipt。人工选择成员、名称、检测日期后，原图写入现有 ServiceRecord（group_service），structuredContent 标注 daily_monitoring_image；不生成 HealthRecord 数值、不触发 OCR。就诊资料仍进入 MedicalReport 待解析。同客户原件摘要去重。
- 附件列表先筛选附件再取最近100份，避免活跃群文字消息挤掉待归档图片。
- SERVICE_GROUP_DAILY_RECORD_ENABLED=true 开启按中国日期汇集新采集文字。使用既有 ServiceGroupEntry 的 record 草稿，不新增记录库或收件箱页面；当前为本地原文摘录，不声称 AI 语义总结。
- 每天同群未编辑草稿持续追加，最多200条或约17000字；人工编辑、确认、取消或达到容量后，后续消息进入补充草稿。消息ID去重，版本冲突重试，不覆盖人工编辑或正式记录。超长消息预览明确提示回原群核对，完整来源仍保留。
- 人工选择成员、核对当日实际沟通并保存草稿后确认，使用同一稳定ID写入现有 ServiceRecord。记录日期采用核对后的沟通日期；未来行动仍沿用已有 FollowUp，不把未来安排记成已完成服务。
- 仅处理启用后采集的新消息，不重放此前跳过的消息，不回填历史正式健康记录；不向群自动发消息。
- 验证：21项相关测试、3项部署安全测试、staff构建通过；430px侧栏合成回归验证跟进任务与日常记录均确认到原系统，图片归档原件及日期通过接口回读验证。未在生产写入合成记录。


## 侧栏简化与专业随访草稿（2026-09-14）

- 主导航仅待跟进、沟通记录、资料归档；资料归档内分群资料与手动上传。群设置和连接诊断位于右上设置；服务总结、群通知、交接回复、快捷指令折叠于更多功能。沿用全部原数据和确认接口。
- 在已有 SERVICE_GROUP_AI_ENABLED 与群 aiConsent 同时启用时，采集进程每轮最多整理一份20秒未更新且未经人工编辑的 task/record 草稿。复用 ai.chat 与 AI 预算控制，记录 service_group_draft 用量来源。
- 草稿按客户反馈、已沟通内容、待核实问题、后续计划整理；每项强制携带原文连续摘录，未提供证据则本次结果不写入。相对日期、患者归属及诊疗判断不自动补齐，最终仍由医护审核。
- 调用前后复核群授权，原文摘要防重复，版本比较避免覆盖并发编辑。新消息重新触发整理；AI失败显示提示并延迟5分钟重试，不回滚消息采集、不生成正式健康记录。已人工编辑或确认草稿不重写。
- 验证：23项相关自动测试通过；360px/430px侧栏导航、折叠与归档方式切换以及原系统确认链路回归通过。现有线上AI服务使用虚构沟通案例完成调用，输出通过原文依据校验。


## 重复请求与取消事项删除（2026-09-14）

- 同群、同发送人、中国同一天的请求按规范化原文去重，兼容星期数字、标点、空格和明确的重复表达尾语；不做模糊语义合并，不合并不同成员或不同日期。兼容最近300条既有任务的旧摘要，取消和已删除项仍参与去重。
- 已取消卡片提供删除入口；后端检查群、成员、编辑权限、版本及关联原系统随访的取消状态。deletedAt 将事项移出侧栏与交接输入，保留来源摘要及操作记录，不物理删除原系统随访。
- AI专业整理持久保留完整来源文本，避免生成摘要后丢失后续去重依据。历史图片、正式记录和已确认随访不批量清理。
- 验证：21项相关测试通过，覆盖旧摘要、重复句、不同日期/成员、取消后删除、删除后防重建；手机侧栏点击删除后卡片消失，并验证原有确认链路正常。staff构建通过。
